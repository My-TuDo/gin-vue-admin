## 二、需求 1：单据列表服务端筛选与分页

### 契约

五个分页端点统一接收 `DocumentSearch`：

- `page`、`pageSize`（默认 1/20，上限 100）；
- `status`（int8）；
- `keyword`（单号、往来单位名称/编码、备注/原因）；
- `warehouseId`、`partnerId`；
- `startAt`、`endAt`（`YYYY-MM-DD`，含当天，`Asia/Shanghai`）；
- `dateField`：`created`（默认）/ `posted`；
- `reversed`：仅采购/销售，`true/false`；
- `sourceType`：仅红冲，`purchase/sale`。

响应仍是 `response.PageResult`，`total` 为数据库真实数量。

### 实现

- 新增 `model/jxc/request/document.go`：`DocumentSearch` + `Normalize()`；
- 新增 `service/jxc/document_search.go`：日期范围、关键词 LIKE 的公共处理；
- 五个 Service 增加 `Search(ctx, info)`，原 `Page(ctx,page,size)` 保留为兼容包装；
- 五个 API 的 page handler 改用 `ShouldBindQuery` + `Search`；
- 采购/销售按 `supplier_id/customer_id` 关联 `jxc_partner` 搜名称/编码；
- 销售退货通过 `sale_order` 关联客户；
- 红冲通过 `sale_order/purchase_order` 关联来源单，支持仓库/往来单位筛选。

### 索引

给单据表补了单列索引（AutoMigrate 生效）：

- `purchase_order`：status / supplier_id / warehouse_id / posted_at；
- `sale_order`：status / customer_id / warehouse_id / posted_at；
- `sale_return`：status / sale_id / warehouse_id / posted_at；
- `purchase_return`：status / purchase_id / supplier_id / warehouse_id / posted_at；
- `stock_reversal`：posted_at。

`created_at` 的复合索引 `(status, created_at)` 还没有加；5 万条压测也还没跑，见第十节。

## 三、需求 2：工作台聚合接口

### 接口

`GET /jxc/dashboard/summary?date=YYYY-MM-DD`，默认今天（Asia/Shanghai）。

返回：

- `date`、`stockValue`、`skuCount`；
- `todaySalesAmount`、`todaySalesOrders`；
- `todayReturnAmount`、`todayReturnOrders`；
- `todayGross`；
- `todayPurchaseAmount`（净采购）；
- `pending`：`approve/receive/ship/purchaseReturnDraft/total`；
- `lowStock`：`threshold/count/items`，`items` 最多 5 条。

### 口径

- 今日销售 = 今日已出库销售 − 今日销售红冲 − 今日已入库销售退货；
- 今日成本 = 对应销售成本 − 红冲成本 − 退货成本；
- 今日毛利 = 今日销售 − 今日成本；
- 今日净采购 = 今日已入库采购 − 今日采购红冲 − 今日采购退货；
- 红冲计入红冲发生日，不追溯改原单日期；
- 待办计数不受分页影响；
- 低库存：`available = 结存 − 有效预留`，`qty >= 0` 且 `available <= 10`，按 available 升序取前 5。

实现：`service/jxc/dashboard_service.go`，全部用 SQL 聚合，不拉列表进内存。

## 五、需求 3：对账作用域与最近结果

### 接口

- `GET /jxc/ledger/reconcile?warehouseId=`：执行一次校验并缓存；
- `GET /jxc/ledger/reconcile/last?warehouseId=`：只读最近结果，不触发扫描。

结果字段：`ok`、`checkedAt`、`durationMs`、`scope`、`checkedSkus`、`count`、
`violations`、`stale`。

### 缓存

- 进程内按 `warehouseId` 缓存（0=全部）；
- TTL 60s；超过 TTL 仍返回结果，但 `stale=true`，前端可显示“上次检查（已过期）”；
- 手动 `reconcile` 会强制刷新并覆盖缓存；
- `/last` 没有记录时返回 `ok=false`、`checkedAt=null`、`stale=true` 的空结果。

壳层目前仍调用同步 `/reconcile`；切换到 `/last` 后进入 `/jxc` 才不会触发全仓扫描。

## 八之二、5 万条列表压测

新增可重复压测 `server/service/jxc/perf_search_test.go`，默认跳过；执行：

```bash
cd server
JXC_PERF=1 go test ./service/jxc -run TestDocumentSearch_Performance50k -v -timeout 30m
```

临时库造数：销售单/采购单/销售退货/采购退货/红冲各 50000 条，共 250000 行；
补复合索引后 `ANALYZE TABLE`，每个查询预热 3 次、测量 20 次。

| 查询 | P50 | P95 |
|---|---|---|
| purchase_page | 21ms | 25ms |
| sale_page | 65ms | 70ms |
| sale_return_page | 68ms | 76ms |
| purchase_return_page | 86ms | 95ms |
| reversal_page | 150ms | 169ms |
| purchase_keyword | 135ms | 156ms |
| sale_keyword | 132ms | 147ms |
| sale_return_keyword | 168ms | 195ms |
| purchase_return_keyword | 145ms | 151ms |
| reversal_keyword | 182ms | 195ms |

结论：全部 P95 < 200ms，低于 `docs/26` 的 300ms 目标。关键词 `LIKE %...%` 是最慢的一组，
但仍可接受；数据量继续增长时应改为前缀/全文索引。

复合索引由 `initialize/gorm_biz_indexes.go` 在 AutoMigrate 后幂等创建，
包括 `(status, created_at)`、`(warehouse_id, created_at)`、`(supplier_id/customer_id, created_at)`、
`(sale_id, created_at)`、`(source_type, posted_at)`。
