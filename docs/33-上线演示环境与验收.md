## 一、决策

- **不引入 Redis**：当前单实例、MySQL 行锁保证账务一致；Redis 的运维/一致性成本大于收益。
  等出现多副本或多门店并发时，再把它作为缓存/协调层引入。
- **销售单数口径**：`todaySalesOrders` / `salesOrders` 保持“已出库单数（含已红冲）”；
  新增 `todaySalesOrdersReversed` / `salesOrdersReversed`；金额/成本/毛利为净额。
  前端显示 `N 单（含 M 张已红冲）`，不再二次扣减。

## 五、演示前重建步骤

### 1. 备份 + 克隆干净演示库

```bash
python scripts/demo-db-reset.py \
  --mysql-password <MySQL密码> \
  --target erp_v3_demo \
  --confirm-target erp_v3_demo
```

脚本会：

1. `mysqldump` 备份源库到 `backups/`；
2. 重建目标库；
3. 导入结构 + 系统表（用户/角色/菜单/casbin）；
4. 清空全部进销存业务表。

### 2. 切配置并重启

把 `server/config.yaml` 的 `mysql.db-name` 改为 `erp_v3_demo`，重启后端。
本地已切换并备份原配置；生产用部署配置，不要改仓库文件。

### 3. 执行 Casbin + seed

```bash
# 演示库第一次必须灌权限
mysql -u root -p erp_v3_demo < docs/sql/jxc-casbin.sql
# 重启后端后：
python scripts/seed-demo.py --password <admin密码> --demo-password <演示密码>
```

### 4. 验收

```bash
python scripts/e2e-smoke.py --password <admin密码>   # 可选；会新增 smoke 数据
```

> e2e 会写冒烟数据，**不要在最终演示库上跑**；需要验收时在临时库跑，或跑完重新 seed。
