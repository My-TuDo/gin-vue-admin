# 18-运行与演示

> 从零把系统跑起来，以及演示数据的重建方式。适用于全新的空 MySQL。

## 一、准备

- MySQL 8/9（本项目在 9.7 上验证）
- Go 1.24+、Node 20+
- 后端配置：`server/config.yaml` 的 `mysql.db-name` 先留空（`""`），其余填好账号密码

```yaml
mysql:
  db-name: ""
  username: root
  password: "你的密码"
  path: 127.0.0.1
  port: "3306"
```

## 二、启动后端并初始化数据库

```bash
cd server
go build -o jxc.exe . && ./jxc.exe      # 端口 8888
```

`db-name` 为空时后端连不上业务库，这是**预期状态**——此时才允许初始化：

```bash
curl -X POST http://127.0.0.1:8888/init/checkdb
# {"code":0,"data":{"needInit":true}}

curl -X POST http://127.0.0.1:8888/init/initdb -H 'Content-Type: application/json' -d '{
  "adminPassword":"Admin@123456","dbType":"mysql","host":"127.0.0.1",
  "port":"3306","userName":"root","password":"你的密码","dbName":"erp_v3"}'
```

初始化会建库、建表、写入管理员，并把 `db-name` 回写到 config.yaml。
**重启后端**让连接切到新库。

> 为什么必须先留空：`/init/checkdb` 的 `needInit` 判定是"能不能连上库"，
> 不是"库里有没有数据"。指向一个已存在的空库时它会说"无需初始化"，
> 结果是表齐了但没有任何账号，登录不上。这个坑我踩过。

## 三、灌入接口权限（必做）

GVA 的鉴权是「角色 + 路径 + 方法」逐条授权的，新模块没有策略时**连 admin 都会被拒**。

```bash
mysql -u root -p erp_v3 < docs/sql/jxc-casbin.sql
```

灌完**必须重启后端**（casbin enforcer 有进程内缓存，不重启会一直报"权限不足"）。

## 四、启动前端

```bash
cd web
npm install
npm run dev        # http://127.0.0.1:8080
```

登录后访问 `http://127.0.0.1:8080/#/jxc`（进销存工作台）。
账号：初始化时设的管理员，密码即 `adminPassword`。

## 五、演示数据

```bash
python scripts/seed-demo.py --password Admin@123456
```

会创建：1 个仓库、2 个商品（4 个规格）、4 笔进货、1 笔销售，并打印台账与对账结果。

> 脚本用 UTF-8 发送请求。**不要用 Windows 终端里的 `curl -d '中文'`** 造数据，
> 会被本地码页破坏成乱码（这个坑也踩过）。

## 六、验收清单（五分钟）

1. 工作台：库存金额、今日销售额、今日毛利三个数不为空；顶栏显示「✅ 账实相符」
2. 开单：点任意规格 → 右侧出现明细 → `Ctrl+Enter` → 提示「已出库 SO-…」并显示毛利
3. 库存：台账能看到结存/预留/可售/均价；点行看到该 SKU 的完整流水
4. 库存 → 一键对账：显示「账实相符」
5. 手工改库验证对账真的有效：

```sql
UPDATE stock_balance SET qty = qty - 2;  -- 故意制造漂移
```

再点「一键对账」，应报出 `qty_mismatch`，并给出「期望 / 实际 / 差额」。
**验完记得改回来**（这条命令是我们对"余额会漂移"的现场证明）。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录提示"验证码错误" | 新库 `sys_security_config.captcha_open=0` 表示**始终**要验证码 | 正常输入验证码；或把该值改成 200（前 200 次不校验） |
| 所有 `/jxc` 接口返回"权限不足" | casbin 策略没灌，或灌了没重启 | 执行第四节 SQL 并重启后端 |
| 接口 500 且响应体为空 | handler panic（GVA recovery 吞掉了栈） | 看后端日志；本次就踩过一次空指针 |
| 页面能开但列表全空 | 数据库指向了旧库（表结构同名但语义不同） | 确认 config.yaml 的 db-name 是新库 |
