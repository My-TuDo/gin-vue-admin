# 18-运行与演示

> 从零把系统跑起来、灌权限、造演示数据、跑冒烟。适用于全新的空 MySQL。

## 一、准备

- MySQL 8/9（本项目在 9.7 上验证）
- Go 1.24+、Node 20+
- 后端配置：`server/config.yaml` 的 `mysql.db-name` 先留空（`""`），其余填好账号密码

```yaml
mysql:
  db-name: ""
  username: root
  password: "你的密码"
  path: 127.0.0.1
  port: "3306"
```

## 二、启动后端并初始化数据库

```bash
cd server
go build -o jxc.exe . && ./jxc.exe      # 端口 8888
```

`db-name` 为空时后端连不上业务库，这是**预期状态**——此时才允许初始化：

```bash
curl -X POST http://127.0.0.1:8888/init/checkdb
# {"code":0,"data":{"needInit":true}}

curl -X POST http://127.0.0.1:8888/init/initdb -H 'Content-Type: application/json' -d '{
  "adminPassword":"Admin@123456","dbType":"mysql","host":"127.0.0.1",
  "port":"3306","userName":"root","password":"你的密码","dbName":"erp_v3"}'
```

初始化会建库、建表、写入管理员，并把 `db-name` 回写到 config.yaml。**重启后端**切到新库。

> 为什么必须先留空：`/init/checkdb` 的 `needInit` 判定是"能不能连上库"，不是"库里有没有数据"。
> 指向一个已存在的空库时它会说"无需初始化"，结果是表齐了但没有任何账号，登录不上。

## 三、灌入接口权限（必做）

GVA 的鉴权是「角色 + 路径 + 方法」逐条授权的，新模块没有策略时**连 admin 都会被拒**。

```bash
mysql -u root -p erp_v3 < docs/sql/jxc-casbin.sql
```

灌完**必须重启后端**（casbin enforcer 有进程内缓存，不重启会一直报"权限不足"）。

矩阵包含 210 条策略、五档角色：

| 角色 | 说明 | 条数 |
|---|---|---|
| 888 | 超级管理员（GVA 自带） | 55 |
| 9001 | 老板：全部 | 55 |
| 9002 | 店长：除红冲与月结 | 53 |
| 9003 | 店员：开单/退货/盘点录入 + 查询 | 25 |
| 8881 | 只读 | 22 |

## 四、启动前端

```bash
cd web
npm install
npm run dev        # http://127.0.0.1:8080
```

登录后访问 `http://127.0.0.1:8080/#/jxc`（进销存工作台，独立于 GVA 后台菜单）。
账号：初始化时设的管理员。

## 五、演示数据与冒烟

```bash
# 造一套可演示数据（2 商品 4 规格、进货、销售）
python scripts/seed-demo.py --password Admin@123456

# 端到端冒烟：采购→销售→退货→超退拦截→红冲→采购原价红冲→采购退货红冲→盘点拦截→原子开单→服务端筛选→对账 last→工作台→月报
python scripts/e2e-smoke.py --password Admin@123456

# 不想处理验证码时，直接复用浏览器里已登录的 x-token
python scripts/e2e-smoke.py --token <x-token>
```

> **登录模式需要临时把 `sys_security_config.captcha_open` 改成 500**，否则登录需要验证码：
> ```sql
> UPDATE erp_v3.sys_security_config SET captcha_open = 500;
> ```
> 跑完记得改回 `0`（0 = 始终要求验证码，是安全默认值）并重启后端。
> 用 `--token` 可以完全绕开这一步。

冒烟脚本每次使用独立的仓库与商品（时间戳后缀），断言只针对本次数据，因此可反复运行；
但系统没有删除接口，演示库会持续累积 smoke 仓库/SKU，这是当前版本的已知限制。

## 五之二、后端测试

```bash
cd server
# 账本/单据集成测试：需要本机 MySQL（root:123456@127.0.0.1:3306），无库会自动 Skip
go test ./service/jxc ./internal/ledger -count=1

# 全量
go test ./... -count=1
```

`service/jxc` 的测试会为每个用例建一个临时库并在结束时删掉，不会污染 `erp_v3`。
`config` 包的 `TestShippedServerConfigsMatchSchema` 会校验 `config.yaml`、
`config.docker.yaml` 与 K8s ConfigMap 是否贴合 `config.Server`；当前三个都通过。

## 六、验收清单（十分钟）

1. **工作台**：库存金额、今日销售额、今日毛利不为空；顶栏显示「✅ 账实相符」
2. **开单**：点规格 → 明细出现 → `Ctrl+Enter` → 提示「已出库 SO-…」并显示毛利
3. **补货**：建单 → 「单据 → 采购单」审核 → 入库 → 台账数量增加
4. **退货**：已出库单点「退货」→ 填数量 → 退货单入库 → 台账增加，成本按原单
5. **红冲**：已出库单点「红冲」→ 填原因 → 台账回退；再点一次应提示「已经红冲过了」。
   **已有退货单的销售单不能再整单红冲**（会提示改用退货处理）
6. **盘点**：发起盘点 → 填实盘数 → 完成 → 台账变成实盘数，流水里出现盘盈/盘亏。
   如果盘点期间又发生了出入库，完成会提示「账面数已变化，请重新盘点」，这是预期拦截
7. **对账**：一键对账显示「账实相符」
8. **报表**：月报四个数合理；点「结账」后该月不能再录单
9. **验证对账真的有效**：
   ```sql
   UPDATE stock_balance SET qty = qty - 2;   -- 人为制造漂移
   ```
   再点「一键对账」，应报 `qty_mismatch` 并给出差额。**验完改回来**。

## 七、常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 登录提示"验证码错误" | 新库 `captcha_open=0` 表示**始终**要验证码 | 正常输入；或临时改 500 |
| 所有 `/jxc` 接口返回"权限不足" | 策略没灌，或灌了没重启 | 执行第三节 SQL 并重启后端 |
| 接口 500 且响应体为空 | handler panic（GVA recovery 吞掉了栈） | 看后端日志 |
| 页面能开但列表全空 | config 指向了旧库（表同名但语义不同） | 确认 `db-name` 是新库 |
| 结账提示"账实不符" | 余额被直接改过 | 先对账处理差异 |
