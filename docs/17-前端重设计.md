# 17-前端重设计

> 客户决定：前端整页重做，不复用旧设计。本文是设计依据，不是实施计划。
> 旧前端（11 个页面、约 5.6k 行）保留在 `feature/jxc-auth-hardening` 分支仅作反面参考。

---

## 一、旧前端到底差在哪（具体说，不笼统）

不是"样式不好看"，是**三个层面的问题**：

1. **一表一页**。每个实体一张 `el-table` + 一个 `el-dialog` 表单，页面之间没有任务流。
   用户想"进一批货"，要在商品、采购、入库三个页面之间跳，心智负担全在用户身上。
2. **弹窗套弹窗**。开单要选商品 → 弹窗选 SKU → 再弹窗改数量，每层都遮挡上下文，
   收银这种高频场景下等于自废效率。
3. **数字没有重量**。库存、金额、成本全用同一个正文字号同一种颜色平铺在表格里，
   店主扫一眼看不出"哪个 SKU 亏了""哪张单还没入库"。

另外两个硬伤：状态用颜色区分但**没有文字**（色弱用户无法分辨）；操作按钮散落在行尾，
每行 4~6 个 icon，误点率高。

---

## 二、设计原则

1. **任务优先，不是实体优先**。一级导航按"我今天要干什么"组织（开单 / 补货 / 盘点 / 看账），
   不按数据表组织。
2. **单据是一等公民**。所有页面都能落到"某张单据 + 它的状态 + 它对账本的影响"。
   账本行要能从单据一键钻取，反之亦然。
3. **账本可见**。库存不是一个数字，是"结存 / 预留 / 可售 / 均价"四个数，
   以及"这些数是怎么来的"（流水）。对账功能必须在一级入口，不能藏在设置里。
4. **密度优先于留白**。这是工作台不是官网：一屏能看到 15~20 行，行高 36~40px，
   数字右对齐、等宽字体。
5. **键盘优先**。开单、收银全流程可不用鼠标：`/` 聚焦搜索、`Enter` 确认、`Esc` 取消、
   `Ctrl+Enter` 提交。
6. **状态永远"颜色 + 文字"**。不靠颜色单独承载信息。

## 三、信息架构

```
┌ 工作台 ────────────────────────────────┐
│ 今日：销售额 / 毛利 / 订单数 / 待入库      │
│ 需要处理：待审核采购 3 · 待出库 2 · 对账异常 0│
│ 最近流水（账本视角，不是"操作日志"）        │
└──────────────────────────────────────┘
┌ 开单（销售）────────────────────────────┐
│ 左：商品搜索/扫码（结果即卡片，含可售量）   │
│ 右：当前单据（明细 / 合计 / 收款）         │
└──────────────────────────────────────┘
┌ 补货（采购）────────────────────────────┐
│ 选供应商 → 加明细 → 提交（草稿）→ 审核 → 入库│
└──────────────────────────────────────┘
┌ 库存 ──────────────────────────────────┐
│ 台账（结存/预留/可售/均价）→ 点行看流水     │
│ 流水（账本行，只读，可钻取到单据）          │
│ 对账（一键校验，列出不一致项）             │
└──────────────────────────────────────┘
┌ 单据 ──────────────────────────────────┐
│ 采购单 / 销售单：按状态分组，支持"下一步操作" │
└──────────────────────────────────────┘
┌ 基础资料 ──────────────────────────────┐
│ 商品与规格（颜色×尺码矩阵）/ 仓库          │
└──────────────────────────────────────┘
```

**只有 6 个一级入口**。旧前端是 11 个平铺页面，其中 3 个（品牌、分类、供应商）
在单店场景下一年点不到几次，不该占一级。

## 四、关键页面设计

### 4.1 开单页（最高频，按收银台标准做）

```
┌───────────────────────────┬──────────────────────────┐
│ [扫码/搜索框            ] │ 单号 SO-20261027-001      │
│ ┌─────┐ ┌─────┐ ┌─────┐  │ 仓库 [主仓 ▾]             │
│ │商品A│ │商品B│ │商品C│  │ ─────────────────────── │
│ │黑/M │ │白/L │ │黑/S │  │ 名称      数量  单价  小计│
│ │可售3│ │可售0│ │可售7│  │ 商品A黑M   1    99.00 99  │
│ └─────┘ └─────┘ └─────┘  │ 商品C黑S   2    59.00 118 │
│                           │ ─────────────────────── │
│ 可售为 0 的卡片置灰+角标   │ 合计 217.00              │
│ 点击即加入，不弹窗         │ 实收 [217.00]  找零 0.00 │
│                           │ [Ctrl+Enter 出库]        │
└───────────────────────────┴──────────────────────────┘
```

要点：**点商品卡片直接进右侧明细，不弹窗**；数量在行内直接改；
可售为 0 的卡片不可点但可见（让人知道"有这款，只是没货"）。

### 4.2 库存台账页

```
仓库 [全部 ▾]   搜索 [        ]   [一键对账]
┌────────┬────────┬────┬────┬────┬──────┬────┐
│ 商品    │ 规格    │结存│预留│可售│ 均价 │操作│
├────────┼────────┼────┼────┼────┼──────┼────┤
│ 卫衣    │ 黑/M   │ 10 │  3 │  7 │ 45.20│流水│
│ 卫衣    │ 白/L   │  0 │  0 │  0 │   —  │流水│
└────────┴────────┴────┴────┴────┴──────┴────┘
```
- 结存 0 用**灰字显示"0"**，不用红色（0 不是错误）
- 可售 < 0 才用红色（真的卖超了）
- 均价为 `—` 表示无成本，鼠标悬停提示"该 SKU 尚无进货成本"

### 4.3 对账页（本系统最该被看见的能力）

点"一键对账" → 结果只有两种，都要说人话：

- 通过：`✅ 账实相符（128 个 SKU，最后一笔流水 14:23）`
- 不通过：表格列出 `仓库 / SKU / 类型 / 账面 / 账本 / 差额`，并给一句解释：
  "余额 7 与账本累加 10 不一致，差额 3 —— 通常是有人直接改过库存表，或某次写入中途失败"

---

### 4.4 一条必须记下来的教训：账本符号 ≠ 展示语义

流水表第一版把 `stock_move.amount` 直接当"金额"显示，出库行就成了 `-264.00`。
用户第一眼读成"这单卖了 -264 元 / 亏了 264 元"——而它其实是**出库成本**。

问题不在符号本身：`amount` 有符号是账本不变量成立的前提（累加必须等于结存金额）。
问题在**把内部表示直接搬到界面**。修正方式：

1. 接口层给 `MoveRow` 增加 `Cost`（恒正）与 `SourceNo`（单号），
   而不是让前端各自 `Math.abs()`——只要有一个地方忘，就又是一次误导。
2. 表格改成「时间 / 单据 / 商品 / 方向 / 数量 / 成本金额」：
   方向用"入/出"文字 + 颜色，数量取绝对值，成本金额恒正并挂 tooltip 说明
   "入库成本（采购价）"或"出库结转成本（出库时冻结）"。
3. 裸 id 也不再上屏：`sku_id` 换商品名+规格，`sale_out#2` 换 `SO-20261027-002`。

**通用原则**：领域模型的字段一旦有"符号/单位/精度"这类内部约定，
就不要让它未经转换直达界面。展示层要有自己的 DTO，并明确每个字段的业务含义。

## 五、组件策略

不直接堆 Element Plus 默认样式，做 4 个薄封装（**薄，不是重造轮子**）：

| 组件 | 封装内容 |
|---|---|
| `MoneyText` | 金额格式化（千分位、两位小数、负数为红）、右对齐、等宽 |
| `StatusTag` | 状态 → (颜色 + 文字) 的映射表，颜色只是一部分信息 |
| `DataTable` | 行高、斑马纹、空态、loading、行点击钻取 |
| `Sheet` | 侧滑抽屉替代大部分弹窗（不遮挡上下文） |

其余继续用 Element Plus（表格、选择器、日期），不自己实现表单控件。

## 六、视觉

- **密度**：正文 13px，行高 36px，表格 40px；一屏 15~20 行。
- **字体**：数字用等宽（`ui-monospace, "SF Mono", Consolas`），金额/数量右对齐——
  扫一列数字时对不齐是最消耗注意力的。
- **色彩语义**：主色沿用 GVA 蓝；金额涨绿跌红；警告琥珀；禁用灰。
  **颜色永远配合文字**，不单独承载状态。
- **层级**：靠字号/字重/间距，不靠边框堆叠。页面里最多一层卡片。

---

## 七、与 GVA 的关系

- 登录、布局、菜单、权限、路由守卫**继续用 GVA**（这是生态，不重写）。
- 业务页面全部新写，放在 `web/src/view/jxc/` 下，按任务命名：
  `workspace/` `sale/` `purchase/` `inventory/` `documents/` `master/`
- 菜单由后端 casbin 菜单表驱动（GVA 机制），前端不硬编码。

---

## 八、验收标准（可执行）

1. 开单一单（3 个 SKU）**全程键盘完成**，不需要鼠标。
2. 从"库存台账"点任意一行，能按 SKU 过滤出它的完整流水，且每条流水能回到来源单据。
3. 对账页在正常数据下显示"账实相符"；手工改库后能显示差额与解释。
4. 一屏 1440×900 下，台账页可见 ≥15 行。
5. 所有状态展示同时有颜色与文字（截图逐页检查）。
