# 09-开发日志

## 文档说明

- **用途**：记录 GVA-JXC（基于 Gin-Vue-Admin 的服装类进销存系统）v1 阶段从任务拆解、开发过程到上线验收的完整过程。
- **适用对象**：项目开发者（土豆饼）本人，作为日常开发记录、进度追踪与复盘依据。
- **维护方式**：每个工作日结束后填写「开发日志」小节；任务完成、状态变化、里程碑达成时同步更新「当前状态记录」与「里程碑记录」。
- **关联文档**：任务拆解依据 `02-系统设计.md` 的模块划分与 `03-数据库设计.md` 的表设计；接口实现对照 `04-接口设计.md`。

## 一、v1 开发任务拆解

### 1.1 模块总览

基于 `02-系统设计.md` 的 6 大业务模块 + 环境搭建 + 权限配置 + 联调测试，v1 共拆解为 **9 个开发单元（M0 ~ M8）**。预估工期按单人开发计算（单位：人天）。

| 编号 | 开发单元 | 主要开发内容 | 预估工期 | 前置依赖 |
|:----:|----------|-------------|:--------:|----------|
| M0 | 环境搭建 | GVA 脚手架、MySQL/Redis 配置、数据库初始化、前后端启动验证 | 3 天 | 无 |
| M1 | 基础资料模块 | 商品分类、品牌、供应商、客户、仓库的 CRUD | 5 天 | M0 |
| M2 | 商品中心模块 | 商品 SPU、SKU、导入导出、上下架 | 5 天 | M1 |
| M3 | 采购中心模块 | 采购单、审核、入库、取消/删除 | 5 天 | M1、M2 |
| M4 | 销售中心模块 | 销售单、出库、退货退款、换货 | 6 天 | M1、M2 |
| M5 | 库存中心模块 | 库存查询、预警、流水、直接出入库 | 4 天 | M2 |
| M6 | 盘点中心模块 | 盘点单、录入盘点数、差异调整 | 4 天 | M1、M2、M5 |
| M7 | 权限与角色配置 | 5 个预设角色、菜单/API/按钮权限 | 2 天 | M0（可穿插） |
| M8 | 联调测试与修复 | 全流程联调、边界用例、缺陷修复 | 5 天 | M1 ~ M7 |
| | **合计** | | **约 39 天**（约 8 个开发周） | |

> 说明：M1、M2 为基础数据，M3 ~ M6 均依赖它们；M7 可与 M1 ~ M6 穿插进行（每完成一个模块就配置对应权限），不必完全串行。

### 1.2 各开发单元子任务拆解

#### M0 环境搭建（预估 3 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| GVA 脚手架拉取 | 拉取 gin-vue-admin 框架，确认 `server/`、`web/` 目录结构与版本 | 0.5 天 |
| 配置文件 | 配置 `config.yaml` / `config.docker.yaml`（MySQL、Redis、JWT、Casbin 等） | 0.5 天 |
| 数据库初始化 | 创建数据库，执行 GVA 初始化（系统菜单、管理员、API 权限种子数据） | 1 天 |
| 前后端启动验证 | 后端 `go run` 启动、前端 `npm run dev`，管理员登录打通 | 1 天 |

**验收标准**：前后端可正常启动，管理员可登录系统并看到 GVA 默认菜单。

#### M1 基础资料模块（预估 5 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| 商品分类管理 | 树形分类 CRUD、排序、启用/停用（对应表 `goods_category`） | 1.5 天 |
| 品牌管理 | 品牌 CRUD、启用/停用（`brand`） | 0.5 天 |
| 供应商管理 | 供应商 CRUD、启用/停用（`supplier`） | 1 天 |
| 客户管理 | 客户 CRUD、等级设置（`customer`） | 1 天 |
| 仓库管理 | 仓库 CRUD、启用/停用（`warehouse`） | 0.5 天 |
| 前端菜单挂载 | 注册 `jxc` 菜单组及基础资料子页面，绑定路由守卫 | 0.5 天 |

> 后端按 `api/jxc`、`service/jxc`、`model/jxc`、`router/jxc` 分包开发；各子模块均含「删除前引用校验」（如分类下存在商品禁止删除）。

#### M2 商品中心模块（预估 5 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| 商品 SPU 后端 | 商品模型 + CRUD + 上/下架（`goods`） | 1.5 天 |
| SPU 导入导出 | Excel 批量导入/导出，导入时校验编码唯一性 | 1 天 |
| SKU 后端 | 按商品维护 SKU（颜色/尺码/条码/价格）、CRUD（`goods_sku`）；创建 SKU 时同步初始化库存记录（`stock`） | 1.5 天 |
| 前端页面 | 商品列表、商品详情、SKU 管理页 | 1 天 |

**验收标准**：商品可挂多 SKU；新增 SKU 后对应仓库的 `stock` 记录自动生成（quantity=0）；已有库存/采购/销售记录的 SKU 禁止删除。

#### M3 采购中心模块（预估 5 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| 采购单 CRUD | 采购单 + 明细（`purchase_order`、`purchase_item`），创建后状态=待审核 | 1.5 天 |
| 采购审核 | 通过（→已审核）/ 驳回（→已取消），仅待审核可操作 | 0.5 天 |
| 采购入库 | 事务内：校验状态 → 逐条增加库存 → 逐条生成流水（`purchase_in`）→ 状态→已入库 → 记录操作日志 | 1.5 天 |
| 取消/删除 | 待审核/已审核可取消（→已取消）；仅待审核可删除 | 0.5 天 |
| 前端页面 | 采购单列表、新建/编辑、审核、入库操作 | 1 天 |

**状态机**：`1 待审核 → 2 已审核（待入库）→ 3 已入库`，`1/2 → 4 已取消`。

#### M4 销售中心模块（预估 6 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| 正常销售 | 创建销售单（校验库存、`lock_quantity` 锁定）→ 出库（扣减库存、生成 `sale_out` 流水、状态→已出库） | 2 天 |
| 退货退款 | 关联原单（`original_order_id`，`order_type=2`）创建退货单 → 退货入库（增加库存 + `sale_return` 流水） | 1 天 |
| 换货 | 关联原单创建换出单（`order_type=3`）+ 换入单（`order_type=4`），事务内一减一增并各记流水 | 1.5 天 |
| 销售取消 | 取消待出库销售单，释放 `lock_quantity`（→已取消） | 0.5 天 |
| 前端页面 | 销售开单、出库、退货、换货操作页面 | 1 天 |

**状态机**：`1 待出库 → 2 已出库`，`1 → 3 已取消`；库存扣减使用 `WHERE quantity >= N` 条件防超卖。

#### M5 库存中心模块（预估 4 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| 库存查询 | 按仓库/SKU/商品多维度筛选实时库存（`stock`） | 1 天 |
| 库存预警 | 低于预警数量的 SKU 高亮提示 | 0.5 天 |
| 库存流水 | 按时间/SKU/业务类型查询变动历史（`stock_log`，7 种 `business_type`） | 1 天 |
| 直接出入库 | 事务内增减库存 + 生成 `direct_in`/`direct_out` 流水（如赠品、损耗） | 1 天 |
| 前端页面 | 库存列表、流水查询、直接出入库弹窗 | 0.5 天 |

#### M6 盘点中心模块（预估 4 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| 创建盘点单 | 选择仓库，自动抓取系统库存快照生成盘点明细（`system_qty`），状态=盘点中 | 1 天 |
| 录入盘点数 | 逐 SKU 录入 `actual_qty`，自动计算 `diff_qty` | 1 天 |
| 完成盘点 | 事务内：筛选 diff≠0 明细 → 逐条调整库存 → 逐条生成 `check_in`/`check_out` 流水 → 状态→已完成 | 1.5 天 |
| 前端页面 | 盘点单操作、盘点记录与差异明细查询 | 0.5 天 |

#### M7 权限与角色配置（预估 2 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| 预设角色创建 | 创建「老板、店长、销售、采购、仓管」5 个角色 | 0.5 天 |
| 菜单/API 权限 | 按 `02-系统设计.md` 6.2 权限矩阵配置菜单与 API 权限 | 1 天 |
| 按钮级权限 | 前端按钮按权限动态显隐（GVA `v-auth` 指令） | 0.5 天 |

#### M8 联调测试与修复（预估 5 天）

| 子任务 | 详细说明 | 预估 |
|--------|----------|:----:|
| 全流程联调 | 采购→审核→入库→销售→出库→退货/换货→盘点全链路走通 | 2 天 |
| 边界用例验证 | 超卖、并发扣减、重复入库、非法状态流转、软删除数据追溯 | 1.5 天 |
| 缺陷修复与收尾 | 修复联调问题、完善交互提示、基础性能优化 | 1.5 天 |

> M8 之后为上线阶段（v1 内测 → 收集反馈 → 正式发布），不纳入 M0~M8 工期，详见「里程碑记录」。

## 二、开发日志模板

### 2.1 填写模板

```markdown
## 2026-XX-XX（开发第 N 天）

### 今日完成
- [ ] 完成的任务一（涉及文件：`server/service/jxc/xxx.go`、`web/src/view/jxc/xxx.vue`）
- [ ] 完成的任务二

### 遇到的问题
- 问题一描述
  - 原因：xxx
  - 解决：xxx（若未解决，状态标记为「待解决」，并登记到「已知问题与待办事项」）
- 问题二描述（已解决/待解决）

### 明日计划
- [ ] 计划任务一
- [ ] 计划任务二
```

### 2.2 填写规则

| 规则项 | 要求 |
|--------|------|
| 日期 | 顶部日期使用当天实际日期，编号连续（开发第 N 天） |
| 今日完成 | 描述结果而非过程，附关键文件路径便于回溯 |
| 遇到的问题 | 明确「原因 → 解决方式」；未解决的问题必须同步登记到第四节「已知问题与待办事项」 |
| 明日计划 | 从「当前状态记录」或任务拆解中取下一步任务，尽量具体可执行 |
| 更新时机 | 模块完成、里程碑达成时，同步更新第三节「当前状态记录」和第五节「里程碑记录」 |

### 2.3 填写示例

```markdown
## 2026-08-03（开发第 5 天）

### 今日完成
- [x] 完成商品分类后端接口（model/jxc/goods.go、service/jxc/goods.go、api/v1/jxc/goods.go）
- [x] 完成分类树形查询与排序功能，联调通过

### 遇到的问题
- GORM 树形查询返回空父节点导致前端渲染异常
  - 原因：分类树未做递归组装，查询仅返回一层
  - 解决：在 service 层递归组装 children，前端 el-tree 正常渲染（已解决）

### 明日计划
- [ ] 开发品牌管理接口与页面
- [ ] 注册 jxc 菜单路由
```
