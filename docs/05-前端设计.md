# 05-前端设计

## 一、概述

本系统前端基于 **Vue 3 + ElementPlus + Vite**，使用 **GVA（Gin-Vue-Admin）** 框架的 Web 脚手架开发。前端只负责界面渲染与交互，业务逻辑与数据校验全部由后端 `server/` 承担，前后端通过 `HTTPS + JSON` 通信。

### 1.1 技术栈

| 技术 | 版本/说明 | 用途 |
|------|-----------|------|
| Vue 3 | Composition API + `<script setup>` | 页面开发 |
| ElementPlus | UI 组件库 | 表单、表格、弹窗、消息 |
| Vite | 构建工具 | 开发服务器与打包 |
| Pinia | 状态管理 | 用户、应用、业务全局状态 |
| Vue Router 4 | 路由管理 | 动态路由 + 路由守卫 |
| Axios | HTTP 客户端 | API 请求封装 |
| ECharts | 图表（可选） | 库存趋势、销售统计 |

## 二、路由设计

### 2.1 路由策略（GVA 动态菜单机制）

本系统沿用 GVA 的「**静态路由 + 后端动态菜单**」策略：

1. **静态路由**：`router/index.js` 中仅注册 `Login`、`Init`、`layout`、`404` 等框架级路由；
2. **动态菜单**：菜单数据（名称、路径、组件路径、图标、排序）存放在后端数据库菜单表中，登录成功后通过 `GET /menu/getMenu` 按用户角色 `authorityId` 拉取，前端 `router.js` store 处理后动态 `addRoute` 注册；
3. **JXC 菜单**：六大模块的菜单在 GVA 菜单管理中配置（或初始化 SQL 写入），绑定角色即可实现按角色显隐，无需修改前端路由代码。

> 好处：进销存菜单的增删、排序、授权全部在系统"菜单管理"界面完成，符合 GVA 惯例，也方便不同店铺按角色裁剪菜单。

菜单数据在 GVA 菜单管理中以树形结构存储（后端表），前端收到的结构如下：

        ]

前端 `router/index.js` 仅保留框架级静态路由：

```js
// web/src/router/index.js（示意，GVA 内置）
export const constantRoutes = [
  {
    path: '/login',
    name: 'Login',
    component: () => import('@/view/login/index.vue'),
    meta: { title: '登录' }
  },
  {
    path: '/',
    name: 'layout',
    component: () => import('@/view/layout/index.vue'),
    redirect: '/dashboard'
    // 业务页面全部由动态菜单在路由守卫中 addRoute 挂载到 layout 下
  }
  // 404 等...
]
```

`router.js` store 负责将菜单数据解析为可注册路由（`utils/asyncRouter.js`），并在登录/刷新时调用：

```js
// web/src/pinia/modules/router.js（示意）
export const useRouterStore = defineStore('router', () => {
  const asyncRouters = ref([])
  const asyncRouterFlag = ref(false)
  // 拉取菜单 → 解析 → addRoute，供 permission.js 调用
  const SetAsyncRouter = async () => {
    const res = await getAsyncRoutes() // GET /menu/getMenu
    const routers = res.data
    routers.forEach(r => asyncRouters.value.push(r))
    asyncRouterFlag.value = true
  }
  return { asyncRouters, asyncRouterFlag, SetAsyncRouter }
})
```

### 2.4 路由守卫逻辑

复用 GVA 的 `permission.js`，核心流程：

```
路由跳转 before
    │
    ▼
┌────────────────────┐
│ NProgress.start()  │
│ 设置页面标题         │
└─────────┬──────────┘
          │
          ▼
┌────────────────────┐  是   ┌──────────────────────────┐
│ 是否白名单路由      ├──────►│ 已有 token？              │
│ Login / Init       │       └────────────┬─────────────┘
└─────────┬──────────┘                    │ 是
          │ 否                            ▼
          ▼                 ┌──────────────────────────┐
┌────────────────────┐     │ 动态路由已注册？           │
│ 是否有 token？      ├──否──► 跳转 Login（携带 redirect）│
└─────────┬──────────┘     └──────────────────────────┘
          │ 是
          ▼
┌────────────────────┐     ┌──────────────────────────┐
│ 动态路由未注册？     ├──是──► 拉取菜单 + 用户信息         │
│ asyncRouterFlag    │     │ SetAsyncRouter()          │
└─────────┬──────────┘     │ addRoute 注册 JXC 菜单路由   │
          │ 否             │ 重新跳转 to                 │
          ▼               └──────────────────────────┘
┌────────────────────┐
│ 放行 / 命中 404      │
└────────────────────┘
```

要点：

| 场景 | 行为 |
|------|------|
| 未登录访问受保护页面 | 重定向 `Login`，携带 `redirect` 参数，登录后回跳 |
| 已登录首次进入 | `Promise.all([SetAsyncRouter(), GetUserInfo()])`，动态注册 JXC 菜单路由 |
| 路由未命中（无匹配） | 跳到 `/layout/404` |
| 登录后访问白名单页 | 若有 token 则重定向到用户 `defaultRouter`（如 `jxcStockQuery`） |
| 401 接口响应 | `request.js` 拦截：清除本地凭证 → 跳转登录页 |

## 四、状态管理（Pinia）

### 4.1 user store（`pinia/modules/user.js`，GVA 内置）

| 状态/方法 | 类型 | 说明 | JXC 使用场景 |
|-----------|------|------|--------------|
| `userInfo` | ref | 用户信息：`nickName`、`headerImg`、`authority`（角色）、`authorityId` | 列表显示"创建人"、订单操作人 |
| `token` | computed | 当前 token（localStorage/cookie 双写） | 请求拦截器自动携带 |
| `authorities` | ref | 用户拥有的全部角色 ID | v-permission 校验 |
| `LoginIn` / `LoginOut` | action | 登录 / 登出 | 登录页 |
| `GetUserInfo` | action | 拉取用户信息 | 路由守卫初始化 |

JXC 侧约定：**不在 user store 中存放业务数据**，仅读取 `userInfo.nickName` 作为 `creator`、`operator` 默认值。

### 4.2 app store（`pinia/modules/app.js`，GVA 内置）

| 状态/方法 | 类型 | 说明 |
|-----------|------|------|
| `sideCollapse` | ref | 侧边栏折叠状态（垂直布局） |
| `toggleSideCollapse(v?)` | action | 切换/设置折叠态，绑定顶部折叠按钮 |
| `device` / `toggleDevice` | ref/action | 设备类型（mobile/desktop），控制抽屉式侧边栏 |
| `layoutZone` | ref | 断点：mobile / pad / desktop |
| `breadcrumbs`（扩展） | computed | 面包屑，由 `route.matched` 派生：`[{title:'进销存'}, {title:'采购管理'}, {title:'采购单列表'}]` |

面包屑派生逻辑（不单独存储，直接计算）：

```js
// 布局顶部导航内（示意）
const route = useRoute()
const breadcrumbs = computed(() =>
  route.matched
    .filter(r => r.meta?.title)
    .map(r => ({ title: r.meta.title, path: r.path }))
)
```

### 4.3 jxc store（`pinia/modules/jxc.js`，★ 业务新增）

| 状态/方法 | 类型 | 说明 |
|-----------|------|------|
| `currentWarehouseId` | ref | 当前操作仓库（localStorage 持久化），默认取启用仓库第一个 |
| `setCurrentWarehouse(id)` | action | 切换当前仓库（入库/出库/盘点默认选中） |
| `stockQuery` | ref | 库存查询页面的筛选偏好：`{warehouseId, categoryId, keyword}` |
| `warehouseOptions` | ref | 启用仓库下拉缓存（`[{id, name}]`），首次访问仓库页拉取 |
| `purchaseDraft` | ref | 创建采购单草稿（防误关页面丢数据） |
| `saleDraft` | ref | 创建销售单草稿 |
| `clearDraft(type)` | action | 清除指定草稿 |

设计约束：

| 存什么 | 不存什么 |
|--------|----------|
| 全局跨页面的业务偏好（当前仓库、筛选偏好） | 单页面内部临时状态（弹窗开关、loading） |
| 跨路由需要共享的数据（仓库下拉缓存） | 可从后端实时拉取且不常变以外的数据 |
| 创建单草稿 | 已提交单据（一律以接口返回为准） |

### 5.1 JxcTable（通用表格）

**职责**：封装 ElementPlus `el-table` + `el-pagination` + 搜索栏 + 工具栏，统一列表页样式与交互。

| Props | 类型 | 默认 | 说明 |

```

```

├──────────────────────────────────────────────────────────────────┤

### 5.2 SkuSelector（SKU 选择器弹窗）

**职责**：采购/销售/盘点场景中按「商品 → 颜色/尺码」维度挑选 SKU 并录入数量。

**打开方式**：`ElDialog` 全屏/大尺寸弹窗，左侧商品筛选，右侧 SKU 表格。

```
┌────────────────────────────────────────────────────────────────┐

│ │关键字搜索  │  │                                                │
│ └───────────┘  └────────────────────────────────────────────────┘

```

| 能力 | 说明 |
|------|------|
| 按商品筛选 | 分类、品牌、关键字（商品名/SKU 编码/条码）筛选商品 |
| 颜色/尺码维度 | SKU 行展示 `color`、`size`，可再按颜色、尺码下拉过滤 |
| 多选 | 表格多选；每行数量可编辑（`el-input-number`，默认 1） |
| 库存提示 | 显示可用库存（`quantity - lock_quantity`），超库存校验并拦截 |
| 回填 | 编辑场景传入 `selected`，回显已选与数量 |
| 确认 | `emit('confirm', [{ skuId, skuCode, goodsId, goodsName, color, size, price, costPrice, qty }])` |

**数据加载**：`goods/sku/page` + 分类树 + 品牌列表 + `stock/available`（按仓库查可用量），仓库参数默认取 `jxc.currentWarehouseId`。

### 5.3 GoodsPicker（商品选择器）

**职责**：单独选择商品（SPU），用于"按商品维度"的筛选/操作场景（如库存查询的赠品、盘点范围选择）。

| Props | 说明 |
|-------|------|
| `v-model` | 选中的商品 `[{id, code, name}]` |
| `multiple` | 是否多选（默认单选） |
| `categoryId` / `brandId` | 打开时预置筛选 |

**行为**：弹窗展示商品表格（编码、名称、分类、品牌、状态），顶部支持分类/品牌/关键字筛选；确认后返回商品列表；与 SkuSelector 的区别：**只选到 SPU 层级，不含颜色尺码数量**，通常用于"先选商品再进入 SKU 明细"的两步式表单。

### 5.4 WarehouseSelect（仓库下拉）

**职责**：所有涉及仓库的业务表单/筛选统一使用的仓库下拉组件。

| Props | 说明 |
|-------|------|
| `v-model` | 仓库 id（Number） |
| `disabled` | 是否禁用 |
| `clearable` | 是否可清空 |
| `defaultCurrent` | 默认选中 jxc 的 `currentWarehouseId` |

**实现要点**：
- 挂载时拉取 `warehouse/status?status=1`（启用仓库），写入 `jxc.warehouseOptions` 缓存，避免每个页面重复请求；
- 采购单/盘点单表单中仓库一旦选择后**锁定禁用**（单据入库仓库不可中途变更）；
- 变更时同步 `jxc.setCurrentWarehouse(id)`。

```vue
<WarehouseSelect v-model="form.warehouseId" default-current />
```

### 5.5 StatusTag（状态标签）

**职责**：将后端 `TINYINT` 状态枚举渲染为带颜色的 `el-tag`，统一状态文案与视觉。

| Props | 说明 |
|-------|------|
| `type` | 业务类型：`category` / `brand` / `supplier` / `customer` / `warehouse` / `goods` / `sku` / `purchase` / `sale` / `saleType` / `check` / `stockLog` |
| `value` | 状态值（Number） |

**内置枚举映射**（与 03-数据库设计一致）：

| type | 值 | 文案 | 颜色 |
|------|----|------|------|
| 通用启停（category/brand/supplier/customer/warehouse） | 1 / 0 | 启用 / 停用 | success / info |
| 商品/ SKU | 1 / 0 | 上架 / 下架（启用/停用） | success / info |
| purchase（采购单） | 1 / 2 / 3 / 4 | 待审核 / 已审核 / 已入库 / 已取消 | warning / primary / success / info |
| sale（销售单） | 1 / 2 / 3 | 待出库 / 已出库 / 已取消 | warning / success / info |
| saleType（单据类型） | 1 / 2 / 3 / 4 | 正常销售 / 退货退款 / 换货出库 / 换货入库 | primary / warning / danger / success |
| check（盘点单） | 1 / 2 | 盘点中 / 已完成 | warning / success |
| stockLog（流水类型） | purchase_in / sale_out / sale_return / check_in / check_out / direct_in / direct_out | 采购入库 / 销售出库 / 销售退货 / 盘点盘盈 / 盘点盘亏 / 直接入库 / 直接出库 | 蓝 / 橙 / 紫 / 青 / 红 / 绿 / 灰 |

> 枚举常量集中在 `constants/jxc.js`，`StatusTag` 与表单下拉选项共用同一数据源，保证前端显示与后端一致。

| 已出库(2) | 详情、退货/换货（从详情发起） | `jxc:sale:return` / `exchange` |
| 已取消(3) | 详情 | - |

工具栏：`新建销售单`、`退货退款`、`换货`（均跳 hidden 路由）。

#### 6.4.2 创建销售单（create.vue）

```
┌──────────────────────────────────────────────────────────────────┐
│ 销售单：单号(自动生成 SO-...)      类型：正常销售(固定)             │
│ [客户 ▾(可空)] [出库仓库 ▾]（选定后锁定）                            │
│                                                      [＋ 添加商品] │
│ SKU明细表（数量可改，超出可用库存时行内校验拦截）                     │

└──────────────────────────────────────────────────────────────────┘
```

要点：
- 客户可空（匿名零售）；
- SKU 选择时显示**可用库存**（`quantity - lock_quantity`），提交时数量不得超过可用库存；
- 售价默认取 SKU `salePrice`，可改（议价场景）；
- 提交即创建「待出库」销售单，后端锁定库存（`lock_quantity` 增加）。

#### 6.4.3 退货退款（return.vue）

```

  │ 原单仅展示 已出库(2) 状态，且未完全退货
  ▼

```

- 原单选择器：`jxcSale` 已出库单据列表弹窗（或输入单号搜索）；
- 退回数量不得大于原单已出库数量减去已退数量（后端校验，前端提示）；
- 确认退货后库存增加，流水 `sale_return`。

#### 6.4.4 换货（exchange.vue）

```
[选择原销售单] ──► 换出：勾选原单 SKU 数量（负向出库）
                ──► 换入：新增商品 SKU 明细（正向入库）
                ──► 提交 → 生成换货出库单(3) + 换货入库单(4)
```

- 表单分上下两个明细区块：**换出明细**（来源原单，数量可改）、**换入明细**（通过 SkuSelector 添加）；
- 提交后创建双单，均关联 `original_order_id`；确认后分别扣减/增加库存并生成流水。

#### 6.4.5 销售单详情（detail.vue）

- 头部：单号、类型、状态、客户、仓库、创建人/时间、备注；
- `orderType != 1` 时展示"关联原单"链接（可跳转原单详情）；

- 操作区按状态显隐：出库/取消/删除；已出库时显示「退货退款」「换货」入口。

## 七、API 封装

### 7.1 axios 实例与拦截器

复用 GVA 的 `web/src/utils/request.js`，对外导出 `service`（axios 实例）。**JXC 所有 API 文件不新建 axios 实例，统一引用该 service。**

请求拦截器行为：

| 项目 | 行为 |
|------|------|
| baseURL | `import.meta.env.VITE_BASE_API`，每个请求可用 `config.baseURL` 覆盖 |
| 请求头 | 自动携带 `x-token`（token）、`x-user-id`（用户 ID）、`Content-Type: application/json` |
| 超时 | 默认 10 分钟（`DEFAULT_REQUEST_TIMEOUT`），可单请求覆盖 |
| Loading | 默认自动全屏/局部 Loading（400ms 延迟出现），`config.donNotShowLoading` 可关闭 |

响应拦截器行为：

| 场景 | 处理 |
|------|------|
| `code === 0` 或 header `success=true` | 直接返回 `response.data`，业务层取 `.data` |
| token 刷新 | 响应头带 `new-token` 时自动写入 user store |
| `code !== 0` | `ElMessage.error` 弹出后端 `msg`（去重，最多同时 3 条） |
| HTTP 401 | 清除本地凭证 → 跳转登录页 |
| 网络错误 / 无响应 | 全局错误通知（`emitter.emit('show-error')`） |
| 其他 HTTP 错误 | 统一错误提示 + `Promise.reject` |

JXC API 规范（示例 `api/jxc/purchase.js`）：

```js

// 创建采购单

  service({ url: '/jxc/purchase/create', method: 'post', data })

// 审核 / 入库 / 取消

  service({ url: '/jxc/purchase/audit', method: 'post', data })

export const inboundPurchase = (data) =>
  service({ url: '/jxc/purchase/inbound', method: 'post', data })

export const cancelPurchase = (data) =>
  service({ url: '/jxc/purchase/cancel', method: 'post', data })
```

## 八、权限控制

权限体系沿用 GVA Casbin RBAC：**菜单权限（前端路由/菜单显隐）+ 按钮权限（界面元素显隐）+ API 权限（后端强制校验）**，前端控制仅用于 UI 呈现，后端仍做最终鉴权。

### 8.1 v-permission 指令

GVA 内置 `v-auth`（按角色 ID 判断）。业务侧封装 **`v-permission`** 指令，支持两种校验维度：

```js
// web/src/directive/permission.js
import { useUserStore } from '@/pinia/modules/user'

export default {
  install: (app) => {
    const userStore = useUserStore()
    app.directive('permission', {
      mounted(el, binding) {
        const { value } = binding
        if (!value) return
        const needPermissions = String(value).split(',')
        const hasPermission = needPermissions.some((perm) => {
          // 1. 按权限标识：userStore.permissions 为当前用户全部按钮标识
          if (userStore.permissions.includes(perm)) return true
          // 2. 兼容 GVA：按角色 ID（数字）
          return String(userStore.userInfo.authorityId) === perm
        })
        const visible = binding.modifiers.not ? !hasPermission : hasPermission
        if (!visible) el.parentNode?.removeChild(el)
      }
    })
  }
}
```

使用：

```vue
<!-- 按钮级：指定权限标识 -->
<el-button v-permission="'jxc:purchase:audit'" @click="audit(row)">审核</el-button>

<!-- 多标识任一满足即可 -->
<el-button v-permission="'jxc:sale:return,jxc:sale:exchange'">售后</el-button>

<!-- 取反：无权限才显示 -->
<el-button v-permission.not="'jxc:check:complete'">只读提示</el-button>
```

`permissions` 集合来源：登录/刷新时由后端根据角色返回按钮权限标识列表，存入 user store（或复用 GVA 的按钮权限 API `authorityBtn`）。

### 8.2 路由权限过滤

- **菜单路由**：后端 `GET /menu/getMenu` 按 `authorityId` 只返回该角色有权的菜单，前端原样注册，天然完成过滤（见 2.4 节守卫流程）；
- **hidden 路由**：创建/详情页按按钮权限跳转，无权限时调用方直接拦截（按钮已隐藏，路由层面由后端 Casbin 兜底返回 403）；
- **defaultRouter**：登录后跳转的角色默认首页可配置为 `jxcStockQuery` 等业务页。

### 8.3 按钮级权限清单

| 模块 | 权限标识 | 对应操作 |
|------|----------|----------|
| 分类 | `jxc:category:add` `jxc:category:edit` `jxc:category:delete` | 新增/编辑/删除 |
| 品牌 | `jxc:brand:add` `jxc:brand:edit` `jxc:brand:delete` | 新增/编辑/删除 |
| 供应商 | `jxc:supplier:add` `jxc:supplier:edit` `jxc:supplier:delete` | 新增/编辑/删除 |
| 客户 | `jxc:customer:add` `jxc:customer:edit` `jxc:customer:delete` | 新增/编辑/删除 |
| 仓库 | `jxc:warehouse:add` `jxc:warehouse:edit` `jxc:warehouse:delete` | 新增/编辑/删除 |
| 商品 | `jxc:goods:add` `jxc:goods:edit` `jxc:goods:delete` `jxc:goods:import` `jxc:goods:export` | 新增/编辑/删除/导入/导出 |

### 8.4 前后端权限协作

```
前端：菜单按角色过滤 → 侧边栏仅显示有权的菜单
前端：v-permission 控制按钮显隐（UI 层）
   │
   ▼ 用户仍可构造请求（防绕过）
后端：Casbin 中间件校验 API（/jxc/* 路由绑定权限）
   │ 无权限 → 403
   ▼
数据权限：data_scope 中间件按部门/角色过滤数据范围
```

> 原则：**前端隐藏 ≠ 安全**，所有 `/jxc/*` 接口在 `router/jxc/` 注册时均绑定 Casbin 权限，前端仅做体验优化。

## 九、前端设计规范

1. **组件复用**：列表页统一使用 `JxcTable`；商品/单据选择统一使用 `GoodsPicker + SkuSelector`；仓库选择统一 `WarehouseSelect`；状态展示统一 `StatusTag`。
2. **权限驱动 UI**：所有影响数据或流程的按钮必须加 `v-permission`，标识见 8.3 清单。
3. **状态集中定义**：订单/盘点/流水枚举只定义一次于 `constants/jxc.js`，表单下拉与状态标签共用。
4. **表单校验前置**：必填、数量>0、超库存、编码重复等校验在提交前完成；金额由前端按 `数量×单价` 实时计算并同步后端校验。
5. **金额展示**：`DECIMAL` 金额统一 `toFixed(2)` 格式化，禁止浮点运算累积误差。
6. **列表分页**：统一 `page` + `pageSize` 参数，接口返回 `{list, total}`，由 `JxcTable` 承载。
7. **草稿保护**：创建采购/销售单使用 `jxc` store 草稿，防误关丢数据。
8. **错误兜底**：请求失败由 `request.js` 统一提示，页面不重复 `catch` 弹错。
