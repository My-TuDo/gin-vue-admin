# 29-原子开单出库（`/jxc/sale/checkout`）

> 状态：**后端已完成并测试通过；前端仍使用两次请求，切换清单见 [`28`](28-前端接入需求.md) 第九节。**
> 背景：`docs/23` 的剩余 P1——“销售开单与出库是两次 HTTP，断网可能留下草稿/预留”。

---

## 一、问题

原流程：

```text
POST /jxc/sale          → 建草稿 + 预留库存
POST /jxc/sale/:id/ship → 出库 + 回填成本
```

两次请求之间断网/进程退出：草稿和有效预留留在库里，库存被占用但没有销售单。
前端之前用“出库失败自动取消草稿”兜底，但只能处理“第二次请求收到失败响应”，
处理不了“第二次请求没发出去/响应丢了”。

---

## 二、接口

`POST /jxc/sale/checkout`

请求体与 `POST /jxc/sale` 相同：

```json
{
  "warehouseId": 1,
  "items": [{"skuId": 12, "qty": 2}]
}
```

可选 query：`occurredAt=2026-10-27 10:00:00`，用于补录。

成功返回完整销售单（含 `items[].costAmt`）：

```json
{
  "code": 0,
  "data": {
    "ID": 100,
    "orderNo": "SO-20261027-001",
    "status": 2,
    "totalAmount": 198,
    "costAmount": 20,
    "postedAt": "2026-10-27T10:15:00+08:00",
    "items": [{"ID": 1, "skuId": 12, "qty": 2, "price": 99, "amount": 198, "costAmt": 20}]
  },
  "msg": "成功"
}
```

---

## 三、事务语义

`SaleService.CreateAndShip` 在一个事务里执行：

1. 校验仓库、SKU、数量，按 SKU 售价计算金额；
2. 生成单号、建销售单、逐行预留；
3. 释放预留并过账出库；
4. 回填每行成本、更新单头 `cost_amount/posted_at/status`。

任何一步失败（可售不足、出库校验失败、并发状态变化等）**全部回滚**：
不会留下销售单、预留或账本行。

实现上把原 `Create`/`Ship` 拆成 `createTx`/`shipTx` 两个事务体，
`Create`/`Ship` 仍保留原有一请求语义，`CreateAndShip` 复用同一套逻辑，避免两份业务规则漂移。

## 四、权限

- 888 超管 / 9001 老板 / 9002 店长 / 9003 店员 可用；
- 8881 只读不可用。

## 六、前端切换

前端开单页把：

```text
createSale(payload) → shipSale(id)
```

替换为：

```text
checkoutSale(payload)
```

并删除“出库失败自动取消草稿”的兜底逻辑（原子接口不再需要）。
成功响应的 `data` 已经是完整单据，可直接算本次销售额/成本/毛利。

---

## 七、保留的旧接口

`POST /jxc/sale` 与 `POST /jxc/sale/:id/ship` 继续保留：

- 兼容旧前端/脚本；
- 补录、先建单后出库的场景仍然合法；
- 新代码优先用 `/checkout`。
