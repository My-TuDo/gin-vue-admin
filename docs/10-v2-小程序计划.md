# v2 计划：进销存配套微信小程序

> 状态：已确认（范围、技术方案、登录方式）
> 前置：无（账号密码登录不依赖微信 appid，可纯本地开发联调）

## 1. 背景与定位

- 在 v1（gin-vue-admin 进销存，PC Web 端）基础上，新增**配套微信小程序**（员工内部工具）
- 小程序与 PC 端**共享同一后端与数据库**（同一份 `/jxc/*` API、同一 JWT 鉴权、同一 casbin 角色权限）
- 定位：**移动场景补充**（查库存、扫码、手机收银、盘点），不替代 PC 的复杂流程操作
- 主体：**个人开发者**（无营业执照，不可认证）→ 凡"认证/支付/商业交易"能力一律不依赖

## 2. 功能范围（已确认：不涉及商业支付的功能全部纳入）

| 模块 | 功能 | 复用接口 | 后端增量 |
|---|---|---|---|
| 登录 | 账号密码登录（含 GVA 验证码）+ 角色权限自动继承 | `/base/login`、`/base/captcha` | 无 |
| **首页（导航页）** | 功能九宫格入口（按里程碑逐步点亮）+ 经营看板缩略（今日销售额/毛利/预警数） | `dashboard/overview` | 无 |
| **看板详情页** | 图表化完整看板：近 N 天趋势折线、热销 TOP 条形、分类占比饼图、库存预警 | `dashboard/trend`、`dashboard/top`、`dashboard/category`、`dashboard/stock-alert` | 无 |
| 销售记录 | 销售单/退货/换货列表与详情 | `sale/page`、`sale/detail` | 无 |
| 扫码查库存 | 扫 SKU 条码/输入编码，查各仓库可售/锁定库存 | `stock/page` | `goods/sku/by-barcode`（小） |
| **扫码枪**（替代无扫码枪商户的收银录入） | 小程序扫码 → 投递到已绑定收银台 → **PC 收银台自动加入购物车**（收银/收款在 PC 完成，小程序不做购物车与收款） | `pos/scan`、`pos/scan/pending`、`pos/scan/confirm`、`pos/session`*（*管理接口见 04-接口设计） | pos 扫码枪模块（6 接口，见 04-接口设计） |
| 收银退款 | 选原单→退款（系统内退货入库，退钱走线下） | `cashier/refundable-orders`、`cashier/refund` | 无 |
| 收银换货 | 选原单→退+换（差额多退少补，记账） | `cashier/exchange` | 无 |
| 扫码盘点 | 扫条码连续录入实盘数→完成盘点 | `stockcheck/page`、`stockcheck/items`、`stockcheck/complete` | 无 |
| 直接出入库 | 移动端临时补录出入库 | `stock/direct-in`、`stock/direct-out` | 无 |
| 客户查询 | 按名称/手机号查客户 | `customer/list` | 无 |

**明确不做（一期）**：微信支付（个人主体不可用）、蓝牙小票打印（硬件兼容性差，排二期）、在线商城/客户下单（另一产品线）、订阅消息通知（个人主体受限）。

## 3. 技术方案

- **前端**：uni-app（Vue3 + Vite 语法），项目放当前仓库 `mini/` 目录（与 server/web 同仓，共用 git 分支规范）
- **工作流**：VS Code 写码 → `npm run dev:mp-weixin` 编译 → 微信开发者工具导入 `mini/dist/dev/mp-weixin` 预览调试
- **后端**：`server/` 增量 = `GET /jxc/goods/sku/by-barcode`（扫码查 SKU）+ **pos 扫码枪模块**（`pos_scan`/`pos_session` 表 + 6 接口：上架/轮询/确认/会话生成/校验/作废，详见 04-接口设计）；登录直接复用 GVA `/base/login`（账号密码 + JWT + casbin）
- **开发期网络**：微信开发者工具勾选「不校验合法域名」→ 直连 `http://127.0.0.1:8888`

### 目录约定

```
gin-vue-admin/
├── server/     # 后端（v2 增量：by-barcode + pos 扫码枪模块）
├── web/        # PC 前端（扫码枪联动：收银台设置/自动加购）
├── mini/       # 🆕 uni-app 小程序（.gitignore 排除 node_modules/dist）
│   └── src/
└── docs/       # 本文档
```

## 4. 里程碑拆解

| 编号 | 内容 | 依赖 |
|---|---|---|
| **M1** | 小程序骨架（uni-app 初始化、请求封装、token 管理）+ 账号密码登录页 + 首页看板 | 无 |
| **M2** | 首页导航化 + 看板详情图表 + 扫码查库存（后端 by-barcode 接口） | M1 |
| **M3** ✅ | **扫码枪**：小程序扫码 → 收银台绑定（PC 设置生成码/小程序绑定一次）→ PC 收银台自动加购 | M2 |
| **M4** ✅ | 扫码盘点 + 直接出入库（**出入库=商品列表点选→SKU 弹层选规格/数量→入明细，扫码二选一**；弹层数量默认 0 不点不加；列表含库存双显示） | M2 |
| **M5** | 销售记录 + 客户查询（收银退款/换货已在 PC 端完成，小程序端不重复实现） | M3 |
| **M6** | 联调测试（沿用 scripts/ 冒烟思路，mini 端人工验收清单）+ 上线准备（备案/HTTPS/域名） | M1~M5 |

> **M1~M3 已交付并合并 develop**（详见 09-开发日志）。M3 关键决策：小程序端**不做购物车/收款**——扫码枪只负责录入，收银全程 PC 端完成（适配无扫码枪商户）；收银台码绑定放 PC「收银台设置」与小程序「我的-绑定收银台」，绑定一次长期有效；重置码后旧码立即作废、小程序需重绑。

## 5. 合规备忘（个人主体能力受限）

**官方明示个人不可用**：手机号快速验证组件（getPhoneNumber）、微信支付（商户号准入不含个人）、卡券、微信认证本身、以及一切"需认证"能力。

**官方未明示但受限**：订阅消息长期模板（限政务/医疗类目）、流量主/直播/发票/收货地址（以后台实际开放为准）。

**个人可用（本项目全部依赖）**：wx.login/openid、wx.request 网络、wx.scanCode 扫码、蓝牙、定位、本地存储、分享。

**上线前置**：域名 + ICP 备案 + HTTPS（强制）；类目选「工具」；提审时功能与类目匹配即可。
