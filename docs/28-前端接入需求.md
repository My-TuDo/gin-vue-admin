> 面向：前端开发。
> 后端实现与测试记录见 [`27-后端配合需求实现`](27-后端配合需求实现.md)。
> 状态：**前端已接入（2026-10-27）**，实现与验收见 [`30-前端接入实现`](30-前端接入实现.md)。
> 目标：把单据页从“取前 100 条在前端筛”切到服务端分页；工作台从 5 个列表切到聚合接口；
> 壳层对账从“每次进入全仓扫描”切到“读最近结果”。

## 一、通用约定

- 统一响应：`{ code, data, msg }`，`code === 0` 成功，其他值直接展示 `msg`。
- 分页响应：`{ list, total, page, pageSize }`，`total` 是数据库真实数量。
- 时间统一按 `Asia/Shanghai`；日期参数格式 `YYYY-MM-DD`，`startAt`/`endAt` 都含当天。
- 金额字段是 number，展示统一走 `MoneyText`，不要再手写 `toFixed`。
- 权限不足可能是 `HTTP 401 / code 7` 或 `HTTP 200 / code 7`，按现有 `request.js` 处理，
  采购退货/工作台这类局部请求不要弹整页错误。

## 二、单据页 `documents/index.vue`

### 2.1 五个列表端点

| Tab | 端点 |
|---|---|
| 销售 | `GET /jxc/sale/page` |
| 采购 | `GET /jxc/purchase/page` |
| 销售退货 | `GET /jxc/return/page` |
| 采购退货 | `GET /jxc/purchase-return/page` |
| 红冲 | `GET /jxc/reversal/page` |

### 2.2 统一查询参数

| 参数 | 类型 | 说明 |
|---|---|---|
| `page` | int | 从 1 开始，默认 1 |
| `pageSize` | int | 默认 20，最大 100 |
| `status` | int | 当前 Tab 的状态；不传=全部 |
| `keyword` | string | 单号、往来单位名称/编码、备注/原因；红冲为红冲号/原单号/原因 |
| `warehouseId` | uint | 可选 |
| `partnerId` | uint | 客户/供应商；红冲通过来源单关联 |
| `startAt` / `endAt` | string | `YYYY-MM-DD`，含当天 |
| `dateField` | string | `created`（默认）/ `posted` |
| `reversed` | bool | 仅采购/销售：是否已整单红冲 |
| `sourceType` | string | 仅红冲：`purchase` / `sale` |

### 2.3 示例

```http
GET /jxc/sale/page?page=1&pageSize=20&status=2&keyword=SO-20261027&dateField=posted&startAt=2026-10-01&endAt=2026-10-31
x-token: <token>
```

```json
{
  "code": 0,
  "data": {
    "list": [
      {
        "ID": 12,
        "orderNo": "SO-20261027-001",
        "customerId": 3,
        "warehouseId": 1,
        "status": 2,
        "totalAmount": 297,
        "costAmount": 15,
        "postedAt": "2026-10-27T10:15:00+08:00",
        "reversedAt": null,
        "items": []
      }
    ],
    "total": 24,
    "page": 1,
    "pageSize": 20
  },
  "msg": "成功"
}
```

### 2.4 前端改造点

1. 当前 Tab 变化、状态按钮变化、关键词/日期/仓库筛选变化时，重新请求**当前 Tab 的端点**；
2. 删除 `pageRows` 的前端 `slice` 和 `activeRows.length` 计数，改用接口 `total`；
3. 分页组件的 `total` 用服务端 `total`，页码变化时带 `page` 重新请求；
4. 关键词输入做 300ms 防抖；切换 Tab 时重置 `page=1`；
5. 状态按钮的计数：**后端本轮不提供聚合计数**。可以：
   - 只显示当前筛选的 `total`；
   - 或对每个状态用 `pageSize=1` 各请求一次拿 `total`（5 个轻量请求）；
   不要再用“当前取回的 100 条”算计数；
6. 空态：`total === 0` 时展示 EmptyState，不要用 `list.length === 0` 判断全部数据。

### 2.5 采购退货列表额外字段

`GET /jxc/purchase-return/page` 的列表项额外返回：

- `supplierName`：供应商名称；
- `warehouseName`：仓库名称；
- `itemCount`：明细行数。

列表表头可以直接使用这些字段；详情抽屉仍用 `items`。

## 四、壳层对账 `shell.vue`

### 4.1 新接口

`GET /jxc/ledger/reconcile/last?warehouseId=`：只读最近结果，不触发扫描。

- 有结果：`{ ok, checkedAt, durationMs, scope, checkedSkus, count, violations, stale }`；
- 无结果：`ok=false, checkedAt=null, count=0, violations=[], stale=true`。

### 4.2 前端行为

1. 进入 `/jxc` 时只调 `/last`，**不要**再自动调 `/reconcile`；
2. `checkedAt` 为空或 `stale=true`：顶栏显示“尚未对账/上次检查已过期”，不要显示“账实相符”；
3. 用户点击顶栏或库存页「一键对账」时，调 `GET /jxc/ledger/reconcile` 强制刷新；
4. 手动检查成功后，用返回值更新顶栏，同时可继续触发现有的 `jxc:reconcile` 事件；
5. 顶栏 title 建议展示：`范围 + 上次检查时间 + 耗时 + SKU 数`。

## 五、报表 `report/index.vue`

`GET /jxc/period/summary?month=YYYY-MM` 新增：

- `purchaseReturnAmount`：本月采购退货金额（正数）；
- `purchaseAmount`：已改为净采购额（采购 − 采购红冲 − 采购退货）。

前端可在“采购金额”旁边补一个“采购退货”小指标；口径说明加一行：

> 采购金额 = 已入库采购 − 采购红冲 − 采购退货；采购退货计入退货发生月，不追溯原采购月。

## 九、原子开单 + 出库（后端已就绪，前端已切）

现有开单页是：

```text
createSale() → shipSale(id)
```

两次请求之间断网会留下草稿/预留。后端新增：

`POST /jxc/sale/checkout`，请求体与 `POST /jxc/sale` 相同：

```json
{
  "warehouseId": 1,
  "items": [{"skuId": 12, "qty": 2}]
}
```

成功返回完整销售单（`status=2`，含 `costAmount` 与每行 `costAmt`）。
失败时建单/预留/账本全部回滚，不会留下草稿。

前端改造：

1. `api/jxc/index.js` 增加 `checkoutSale = (data) => POST /jxc/sale/checkout`；
2. 开单页提交改为只调一次 `checkoutSale`；
3. 删除“出库失败自动 cancelSale”的兜底；
4. 用响应 `data` 直接展示本次销售额/成本/毛利。

权限：888/9001/9002/9003 可用；8881 只读不可用。
详细事务语义与测试见 [`29-原子开单出库`](29-原子开单出库.md)。
