# 19-操作手册（店主视角）

> **实现核对（2026-10-27）**：期初建账必须同时填**成本单价**，否则库存金额为 0；
> 已发生退货的销售单不能整单红冲；盘点期间有出入库时，完成会被拒绝并要求重新盘点。
> 这些是本次修复后的行为，旧文档没有写清。差异清单见
> [`21-接手审计`](21-接手审计.md)。

## 一、第一次使用

1. 登录（地址与账号由部署人员提供）
2. 进「基础资料」建立三样东西：**仓库 → 商品（含颜色/尺码）→ 供应商**
   - 建好后可在同一页「编辑」；不再使用的商品/规格/仓库/往来单位请用「停用」，
     不要删除——历史单据和账本还引用着它们。停用的规格不能再开单，但历史数据照常可查。
3. 进「补货」开第一张采购单，审核后入库，库存就有了

> 商品规格（颜色×尺码）是库存与成本的单位。同款不同码算两个 SKU，
> 库存、成本、条码都单独记。

### 期初建账（只做一次）

系统没有"直接改库存"的入口，期初库存通过**盘点**录入：

1. 进「库存 → 盘点」→ 选仓库 → 「发起盘点」
   （此时所有商品账面都是 0）
2. 逐行填**实盘数**（仓里实际有多少）
3. **盘盈行填「成本单价」**（这批期初货的进货价）。不填成本，库存数量会进来，
   但库存金额是 0，之后卖出去会显示接近 100% 的毛利
4. 点「完成」——系统按差异生成"盘盈"记录，库存数量与金额一起就有了

> 为什么不做"导入 Excel"：盘点是同一个动作的可视化版本，而且**留了痕迹**——
> 以后能查到"期初是谁在什么时候盘的"。批量导入以后可以加，但底层仍然是这条盘盈路径。
>
> 注意：盘点建单后如果又发生了销售/入库，完成会被拒绝，要求重新盘点；
> 这是为了防止按过期账面数调账，不是故障。

## 二、每天怎么用

### 开单（卖货）

左侧点规格卡片加入右侧明细 → 改数量 → 「出库（Ctrl+Enter）」。

- 卡片上显示的是**可售**（结存 − 已被订单占用）
- 可售为 0 显示「缺货」并置灰
- 出库成功后，页面会显示这一单的**销售额 / 成本 / 毛利**
- 键盘：`/` 聚焦搜索、`Ctrl+Enter` 出库、`Esc` 清空

### 补货（进货）

选供应商 → 选仓库 → 加明细（规格、数量、进价）→ 提交。

提交后是**草稿**，还要在「单据 → 采购单」里点「审核」，再点「入库」。
**只有入库才会真正增加库存**，审核只是确认。

### 单据（所有单据的入口）

四个标签页：

| 标签 | 能做什么 |
|---|---|
| 销售单 | 草稿可「出库」「取消」；已出库可「退货」「红冲」 |
| 采购单 | 草稿「审核」；已审核「入库」；已入库可「红冲」 |
| 退货单 | 草稿「入库」；可「取消」 |
| 红冲记录 | 只读，查历史冲销 |

**退货 vs 红冲，别选错：**

- **退货**：客户真的把货退回来了，可能只退一部分 → 用「退货」
- **红冲**：单子录错了（价格、数量、客户全错了）→ 用「红冲」，整单作废

红冲必须填原因（以后查账就靠这句话）。红冲不可撤销，也不能重复。
**同一张销售单如果已经开过退货单（哪怕还是草稿），就不能再整单红冲**：
否则退货回补一次、红冲又回补一次，库存会多出来。

### 库存

**台账**：每个 SKU 的结存 / 预留 / 可售 / 均价 / 结存金额。
点任意一行 → 抽屉里是这个 SKU 的流水，每笔都带**结存**（这笔之后还剩多少）；
超过 200 条时可以点「加载更多」，结存由后端按过账顺序计算，翻页也不会错。

**对账**：点「一键对账」。

- 显示「账实相符」= 账面和流水完全一致
- 显示异常 = 会列出仓库、SKU、期望值、实际值、差额，并提示可能原因
- **对账不通过时不能月结**（这是强制的）

**盘点**：发起盘点 → 逐行填实盘数 → 完成。

- 账面数是发起那一刻的快照，后续出入库不会改动它
- 但如果建单后账面确实发生了变化，完成盘点会被拒绝，要求重新盘点（避免按过期差异调账）
- 盘盈行要填**成本单价**，否则库存金额会是 0
- 差异会生成"盘盈/盘亏"的账本记录，**不会直接改库存数字**
- 同一仓库同时只能有一张进行中的盘点单

### 报表

选月份 → 看四个数：净销售额、净成本、毛利、期末库存。

- 净销售额 = 本月出库的销售 + 本月红冲（负数）− 本月已入库退货
- 净成本 = 对应单据上冻结的成本，同样加减红冲与退货
- 红冲计入**红冲发生的月份**，不会回头改原单所在月份的报表
- 期末库存 = 截止该月末的账本累加金额，不是"现在的库存"

**结账**：点「结账」后，这个月不能再录单，库存快照被冻结。
漏录的单只能补到**仍处于打开状态**的月份；已结账月份不能改，只能在本月红冲。

## 三、常见问题

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 点「出库」提示可售不足 | 结存不够，或已被其他未出库的单占用 | 看台账的可售，或取消占用中的单 |
| 采购单入库后库存没变 | 只点了「审核」没点「入库」 | 到「单据 → 采购单」点「入库」 |
| 想看某件货怎么少了 3 件 | — | 库存台账点该行 → 看流水，每笔都有单据号和结存 |
| 红冲时提示"已卖出不能红冲" | 这批货已经卖掉一部分，整单冲回会变负库存 | 用「退货」退给供应商走盘亏，或先退客户单 |
| 结账时提示"账实不符" | 有人直接改过数据库 | 先到「库存 → 对账」看差额，联系维护者处理 |
| 月报数字和上个月不一样了 | 上个月被结账了（快照冻结），或本月补录了上月单据 | 已结账月份的数字不会再变，这是预期行为 |

## 四、角色与权限

| 角色 | 能做什么 |
|---|---|
| 老板 | 全部 |
| 店长 | 除**红冲**和**月结**（这两件影响历史账，需老板决定） |
| 店员 | 开单、出库、退货、盘点录入、查库存与价格；不能采购入库、不能红冲、不能结账 |
| 只读 | 只能查 |

权限在「系统管理 → 角色管理」里分配给账号。

## 五、给老板的三条建议

1. **每天关店前点一次「一键对账」**。账不平能当天发现，比月底翻账本强。
2. **每月 1 号结上个月的账**。结完账，那个月的数字就固定了，以后对比才有意义。
3. **不要直接改数据库**。系统故意不提供"改库存"的按钮——所有变动都要有单据，
   这样出了事能查到是谁、什么时候、因为什么。

## 六、附录：本版本的范围

**已包含**：基础资料（仓库/商品规格/往来单位）、采购（审核→入库）、销售（开单即预留→出库）、
退货、红冲、盘点（含期初建账）、库存台账与流水、一键对账、月报与月结、五档权限。

**未包含**（如需请提需求）：

- 小程序（扫码枪投递、手机查库存）——旧版有，本次重写未纳入
- 多仓库调拨、批次/序列号追踪
- 主数据的硬删除（历史单据引用它们，只提供停用；这是有意的约束）
- 单据打印与导出（小票、对账单）
- 会员、储值、促销折扣

> 这些不是"忘了做"，是刻意排在核心账本之后——账本不对，上面的功能越多越危险。
