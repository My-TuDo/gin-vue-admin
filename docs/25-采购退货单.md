# 25-采购退货单（后端）

> 状态：**后端已完成，前端已接入（2026-10-27）**。
> 后端设计与测试保留在本文；前端接入实现见第七节。

---

## 一、为什么需要它

采购红冲解决的是“整张采购单录错了”，要求整单反向、库存足够。
现实里更常见的是“这批货买多了/有质量问题，退一部分给供应商”，它是一笔真实业务，
不是红冲。没有独立单据时，只能走盘亏或先红冲再补单，账上分不清“退给供应商”和“盘亏”。

采购退货单补的就是这条路径：

- 可以只退一部分；
- 金额按**原采购单价**计算；
- 账本产生一条负向移动（出库），库存与金额一起减少；
- 过账时校验库存与已退上限，不允许退成负数或超退。

---

## 二、数据模型

新增两张表（`AutoMigrate` 已注册）：

| 表 | 作用 |
|---|---|
| `purchase_return` | 退货单头：单号、原采购单、供应商、仓库、状态、金额、过账时间 |
| `purchase_return_item` | 明细：SKU、数量、原采购单价、金额 |

状态：`1 草稿 → 2 已退货`；草稿可以取消为 `3 已取消`。

关键字段：

- `purchase_id` / `purchase_no`：原采购单及单号快照；
- `warehouse_id` / `supplier_id`：从原采购单带出，客户端传值无效；
- `unit_cost`：原采购单价（同一 SKU 多行采购时按总金额/总数量取加权原价）；
- `amount`：退货金额，等于 `qty × unit_cost`。

---

## 三、过账规则

`PurchaseReturnService.Post` 在一个事务里：

1. 锁退货单与采购单，校验状态与是否已整单红冲；
2. 重新统计“已退数量”，防止两张草稿叠加超退；
3. 组装负向 `MoveInput`：`qty = -退货数量`、`unit_cost = 原采购价`、金额精确为负；
4. 交给 `LedgerService.Post`；
5. 成功后把退货单置为已退货并写 `posted_at`。

为什么金额要精确传入：出库默认走当前移动加权平均，但供应商是按原采购价退款的。
如果账上按今天的均价减成本，供应商退款与库存成本会差出一块“凭空利润/亏损”。
所以采购退货和销售退货一样，走 `AmountOverride`，按原采购单价精确出库。

边界：

- 库存不足：`ApplyAmount` 直接拒绝，退货单保持草稿；
- 有有效预留导致可售不足：同样拒绝（不能把已承诺给销售单的货退给供应商）；
- 按原价冲减后结存金额会变成负数：拒绝，并提示当前库存不足以承担该批成本；
- 原采购单已整单红冲：拒绝；
- 已退数量达到原采购数量：`returnable` 返回 `canReturn=0`，再建单直接拒绝。

## 四、接口

统一响应 `{code,data,msg}`，鉴权 `x-token`。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/jxc/purchase-return` | `{purchaseId,items:[{skuId,qty}],reason?}` → 草稿 |
| GET | `/jxc/purchase-return/page?page=&pageSize=` | 列表 |
| GET | `/jxc/purchase-return/:id` | 详情（含 items） |
| GET | `/jxc/purchase-return/returnable?purchaseId=` | 每个 SKU 还能退多少 |
| POST | `/jxc/purchase-return/:id/post` | 退货出库 |
| POST | `/jxc/purchase-return/:id/cancel` | 仅草稿可取消 |

账本流水的 `source_type` 为 `purchase_return`，`sourceNo` 会显示 `PR-YYYYMMDD-NNN`。

## 九、采购退货红冲（2026-10-27 补）

退错了不能只靠盘盈：采购退货单已支持**整单红冲**，复用现有 `POST /jxc/reversal`。

```json
{ "sourceType": "purchase_return", "sourceId": 12, "reason": "供应商取消退货" }
```

语义：

- 只允许已退货（`status=2`）且未红冲的采购退货单；
- 反向账本行数量/金额为正，按原退货单价精确加回库存；
- 采购退货单写 `reversed_at`，不改变原状态；
- 红冲后该退货单不再占用“已退数量”，同一批货可以重新退货；
- 重复红冲被唯一索引 + `reversed_at` 双重拦截。

前端工作（已完成 2026-10-27）：

1. 采购退货列表/详情对已退货且 `reversedAt` 为空的行增加「红冲」；
2. 复用现有红冲原因弹窗，`sourceType` 传 `purchase_return`，弹窗文案区分采购退货；
3. 红冲后刷新列表，显示“已红冲/原状态：已退货”；
4. 权限与销售/采购红冲一致（888/9001 可用，9002 店长不可用）；
5. 红冲记录 Tab 来源显示「采购退货」，原单号为 PR 单号。

验收：`PR-20261027-004` 出库后红冲生成 `RC-20261027-018`，库存 12→13，
列表行变「已红冲」、红冲记录来源「采购退货」；对账 ok=true/count=0。详见 `31`。
