## 1. 环境要求

| 组件 | 最低要求 | 本项目实际使用 | 说明 |
| --- | --- | --- | --- |
| Go | 1.21+ | 1.24（`server/go.mod` 声明 `go 1.24.0`） | 手动编译后端时使用，Docker 部署不需要本机安装 |
| Node.js | 18+ | 20（`web/Dockerfile` 使用 `node:20-slim`） | 构建前端时使用，建议 20+；包管理器为 pnpm（Corepack 自带） |
| MySQL | 8.0+ | 8.0.21（Docker 镜像） | 必须支持 utf8mb4 字符集 |
| Redis | 可选 | 6.0.6（Docker 镜像） | 默认 `system.use-redis: false`，仅启用 Redis 相关功能时才需要 |
| Docker & Docker Compose | 可选 | — | Docker 部署方式必需，手动部署可不安装 |

> 操作系统推荐 Ubuntu 22.04/24.04、Debian 12、CentOS 7+ 等 Linux 发行版。

## 2. Docker 部署（推荐）

项目仓库已内置 Docker 编排文件与镜像构建文件：

```text
deploy/docker-compose/docker-compose.yaml   # Compose 编排（MySQL + Redis + 后端 + 前端）
server/Dockerfile                           # 后端镜像（多阶段构建，运行时 alpine）
web/Dockerfile                              # 前端镜像（pnpm 构建 + nginx:alpine 托管）
web/.docker-compose/nginx/conf.d/my.conf    # 前端容器内 Nginx 配置（/api 反向代理到后端）
```

### 2.1 docker-compose.yml 编排

仓库自带编排文件（`deploy/docker-compose/docker-compose.yaml`）内容如下：

```yaml
version: "3"

# 声明一个名为 network 的 networks，subnet 为 network 的子网地址，默认网关是 177.7.0.1
networks:
  network:
    ipam:
      driver: default
      config:
        - subnet: '177.7.0.0/16'

# 设置 mysql，redis 持久化保存
volumes:
  mysql:
  redis:

services:
  web:
    build:
      context: ../../web
      dockerfile: ./Dockerfile
    container_name: gva-web
    restart: always
    ports:
      - '8080:8080'
    depends_on:
      - server
    command: [ 'nginx-debug', '-g', 'daemon off;' ]
    networks:
      network:
        ipv4_address: 177.7.0.11

  server:
    build:
      context: ../../server
      dockerfile: ./Dockerfile
    container_name: gva-server
    restart: always
    ports:
      - '8888:8888'
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    links:
      - mysql
      - redis
    networks:
      network:
        ipv4_address: 177.7.0.12

  mysql:
    image: mysql:8.0.21       # arm64 架构（如 Mac M1）请改为 image: mysql/mysql-server:8.0.21
    container_name: gva-mysql
    command: mysqld --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    restart: always
    ports:
      - "13306:3306"          # 宿主机 13306 端口映射到容器 3306
    environment:
      #MYSQL_ROOT_PASSWORD: 'Aa@6447985'   # root 用户密码（默认被注释）
      MYSQL_DATABASE: 'qmPlus'             # 启动时自动创建的数据库名
      MYSQL_USER: 'gva'                    # 启动时自动创建的应用用户
      MYSQL_PASSWORD: 'Aa@6447985'         # 该用户密码
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "gva", "-pAa@6447985"]
      interval: 10s
      timeout: 5s
      retries: 3
    volumes:
      - mysql:/var/lib/mysql
    networks:
      network:
        ipv4_address: 177.7.0.13

  redis:
    image: redis:6.0.6
    container_name: gva-redis
    restart: always
    ports:
      - '16379:6379'
    healthcheck:
      test: ["CMD-SHELL", "redis-cli ping | grep PONG || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 3
    volumes:
      - redis:/data
    networks:
      network:
        ipv4_address: 177.7.0.14
```

**架构说明**

- 四个容器通过自定义网络 `network`（网段 `177.7.0.0/16`）互联，使用固定 IP：
  - `gva-web`（177.7.0.11）：Nginx 托管前端静态资源，监听 8080；
  - `gva-server`（177.7.0.12）：后端服务，监听 8888；
  - `gva-mysql`（177.7.0.13）：MySQL 8.0，容器内 3306；
  - `gva-redis`（177.7.0.14）：Redis 6.0，容器内 6379。
- 前端容器内 Nginx 的 `my.conf` 将 `/api` 前缀请求重写后反向代理到
  `http://177.7.0.12:8888`（后端容器固定 IP）。若你修改了网段或固定 IP，必须同步修改
  `web/.docker-compose/nginx/conf.d/my.conf` 后再重新构建前端镜像。
- 后端容器使用 `config.docker.yaml` 启动（见 `server/Dockerfile` 的
  `ENTRYPOINT ./server -c config.docker.yaml`），该配置中 `mysql` 段为空，
  首次启动后需通过**前端初始化向导**填写数据库连接信息完成建表与基础数据写入（详见 2.4）。

**生产环境定制建议**

```yaml
volumes:

  redis:
  uploads:            # 新增：上传文件持久化

services:
  web:
    build:
      context: ../../web
      dockerfile: ./Dockerfile
    container_name: gva-web
    restart: always
    ports:
      - '8080:8080'
    depends_on:
      - server
    command: [ 'nginx-debug', '-g', 'daemon off;' ]
    networks:
      network:
        ipv4_address: 177.7.0.11

  server:
    build:
      context: ../../server
      dockerfile: ./Dockerfile
    container_name: gva-server
    restart: always
    ports:
      - '8888:8888'
    depends_on:
      mysql:
        condition: service_healthy
    networks:
      network:
        ipv4_address: 177.7.0.12
    volumes:
      # 上传文件持久化到宿主机命名卷（对应配置 local.store-path: uploads/file）
      - uploads:/go/src/github.com/flipped-aurora/gin-vue-admin/server/uploads
      # 日志目录持久化（对应 zap.director: log）
      - ./logs:/go/src/github.com/flipped-aurora/gin-vue-admin/server/log

  mysql:
    image: mysql:8.0.21
    container_name: gva-mysql
    command: mysqld --character-set-server=utf8mb4 --collation-server=utf8mb4_unicode_ci
    restart: always
    ports:
      - '127.0.0.1:13306:3306'        # 仅本机可访问，生产环境不要把 3306 暴露公网
    environment:
      MYSQL_ROOT_PASSWORD: 'CHANGE_ME_ROOT_PASSWORD'   # 生产环境必须修改
      MYSQL_DATABASE: 'qmPlus'
      MYSQL_USER: 'gva'
      MYSQL_PASSWORD: 'CHANGE_ME_DB_PASSWORD'          # 生产环境必须修改
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-u", "gva", "-pCHANGE_ME_DB_PASSWORD"]
      interval: 10s
      timeout: 5s
      retries: 3
    volumes:
      - mysql:/var/lib/mysql
    networks:
      network:
        ipv4_address: 177.7.0.13
```

> 若确定不使用 Redis，可移除 `redis` 服务、`server.depends_on` 中的 `redis` 与
> `links`，并保持后端配置 `system.use-redis: false`（默认即为 false）。

### 2.2 构建与启动命令

在**仓库根目录**执行：

```bash
# 构建并启动全部服务（首次构建会拉取依赖，耗时较长）
docker compose -f deploy/docker-compose/docker-compose.yaml up -d --build

# 查看容器状态
docker compose -f deploy/docker-compose/docker-compose.yaml ps

# 查看日志（后端 / 前端）
docker compose -f deploy/docker-compose/docker-compose.yaml logs -f server
docker compose -f deploy/docker-compose/docker-compose.yaml logs -f web

# 停止服务（不删除数据卷）
docker compose -f deploy/docker-compose/docker-compose.yaml stop

# 停止并删除容器（-v 会同时删除数据卷，慎用！）
docker compose -f deploy/docker-compose/docker-compose.yaml down
```

也可以先把编排文件复制到部署目录再操作：

```bash
cp deploy/docker-compose/docker-compose.yaml /opt/gva-jxc/
cd /opt/gva-jxc
docker compose up -d --build
```

启动完成后访问：

- 前端页面：`http://<服务器IP>:8080`
- 后端 Swagger：`http://<服务器IP>:8888/swagger/index.html`
- MySQL 宿主机端口：`13306`；Redis 宿主机端口：`16379`

### 2.3 环境变量说明

| 环境变量 | 作用对象 | 说明 |
| --- | --- | --- |
| `MYSQL_DATABASE` | mysql 容器 | MySQL 容器首次启动时自动创建的数据库名，默认 `qmPlus` |
| `MYSQL_USER` / `MYSQL_PASSWORD` | mysql 容器 | 自动创建的应用账号（非 root），默认 `gva` / `Aa@6447985` |
| `MYSQL_ROOT_PASSWORD` | mysql 容器 | root 密码（文件中默认被注释，生产环境建议启用并设置强密码） |
| `GVA_CONFIG` | server 进程 | 指定后端配置文件路径（优先级：命令行 `-c` > 该环境变量 > gin 模式默认文件）。Docker 内通过 `-c config.docker.yaml` 指定，一般无需设置 |
| `TZ` | server 容器 | 容器时区，`server/Dockerfile` 已设为 `Asia/Shanghai` |
| `VITE_BASE_PATH` | 前端构建 | `.env.production` 中的线上域名，仅「表单构建工具」等在线功能使用，构建时注入，修改后需重新构建前端镜像 |

> 说明：后端配置以 YAML 文件为准（Viper 加载），框架本身不提供逐项配置的
> 环境变量覆盖；需要改连接信息时直接改配置文件（Docker 场景可挂载覆盖
> `config.docker.yaml`）。

### 2.4 首次初始化（前端向导）

1. 浏览器打开 `http://<服务器IP>:8080`；
2. 后端检测到数据库未初始化时，前端会**自动跳转到初始化向导页面**；
3. 在向导中填写数据库连接信息（需与 mysql 容器一致）：
   - 数据库类型：`MySQL`
   - Host：`mysql`（容器名，或固定 IP `177.7.0.13`）
   - 端口：`3306`（容器内端口）
   - 数据库名：`qmPlus`
   - 用户名：`gva`
   - 密码：与 `MYSQL_PASSWORD` 一致
4. 设置管理员账号与密码；
5. 点击「初始化」，系统自动建表并写入基础数据（菜单、API、Casbin 权限、字典等），
   完成后自动跳转登录页。

> 若跳过向导、希望初始化后不再出现向导页，可考虑将后端 `mysql` 连接信息直接写入
> `config.docker.yaml` 并挂载进容器，同时保持 `system.disable-auto-migrate: false`
> 让 GORM 自动建表。基础数据仍需通过向导或初始化脚本写入。

### 2.5 数据持久化配置

- **MySQL**：`mysql:/var/lib/mysql` 命名卷，保存数据库文件；
- **Redis**：`redis:/data` 命名卷（若启用 Redis）；
- **上传文件**：默认 `local.store-path: uploads/file`（相对于后端工作目录）。
  生产环境务必挂载持久化卷（见 2.1 定制版中的 `uploads` 卷），否则
  `docker compose down` 会丢失上传的图片/文件；
- **日志**：`zap.director: log`，可挂载 `./logs` 到宿主机便于采集（见定制版示例）。

命名卷数据可通过 `docker volume ls` 查看，备份时先停止容器再复制卷目录。

## 3. 手动部署

手动部署将后端与前端分别部署在宿主机上（systemd 管理后端进程，Nginx 统一入口）。

### 3.1 数据库初始化

**（1）安装并启动 MySQL 8.0+**（以 Ubuntu 为例）

```bash
sudo apt update
sudo apt install -y mysql-server
sudo systemctl enable --now mysql
```

**（2）创建数据库与专用账号**

```sql
-- 使用 root 登录 MySQL 后执行
CREATE DATABASE IF NOT EXISTS `qmPlus`
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER 'gva'@'%' IDENTIFIED BY '你的强密码';
GRANT ALL PRIVILEGES ON `qmPlus`.* TO 'gva'@'%';
FLUSH PRIVILEGES;
```

> 注意：MySQL 8 默认认证插件为 `caching_sha2_password`，项目使用的
> `go-sql-driver/mysql` 支持该插件，通常无需处理；若连接报
> `authentication plugin` 错误，可改用 `mysql_native_password`：
> `ALTER USER 'gva'@'%' IDENTIFIED WITH mysql_native_password BY '你的强密码';`

**（3）表结构与基础数据初始化（二选一）**

- **方式 A（推荐，可视化）**：保持后端配置 `system.disable-auto-migrate: false`，
  配置好 `mysql` 连接后启动后端，浏览器打开前端地址，进入**初始化向导**
  （`POST /api/init/checkdb` 检测 + `POST /api/init/initdb` 执行），
  按提示完成建表、写入基础数据与管理员账号；
- **方式 B（生产，手动迁移）**：将 `system.disable-auto-migrate` 设为 `true`，
  自行管理表结构迁移（GORM AutoMigrate 不会自动执行）。此时需在开发/预发布环境
  先完成一次初始化，将生成的表结构与 `server/source/` 下的基础数据脚本应用到生产库。

### 3.2 后端部署

**（1）编译后端**

```bash
cd server
go env -w GO111MODULE=on
go env -w GOPROXY=https://goproxy.cn,direct
go mod tidy
go build -o server .          # 生成二进制 ./server
```

**（2）配置 config.yaml**

复制 `server/config.yaml` 到部署目录（如 `/opt/gva-jxc/server/config.yaml`），
按 [第 4 章](#4-配置说明) 修改数据库连接、JWT 密钥、日志与上传配置。

**（3）准备运行目录**

```bash
sudo mkdir -p /opt/gva-jxc
sudo cp server /opt/gva-jxc/
sudo cp config.yaml /opt/gva-jxc/
sudo cp -r resource /opt/gva-jxc/       # 静态资源（Dockerfile 中也会拷贝）
sudo mkdir -p /opt/gva-jxc/uploads/file # 上传目录
sudo mkdir -p /opt/gva-jxc/log          # 日志目录
```

**（4）systemd 服务**

创建 `/etc/systemd/system/gva-server.service`：

```ini
[Unit]
Description=GVA JXC Server
After=network.target mysql.service
Wants=mysql.service

[Service]
Type=simple
WorkingDirectory=/opt/gva-jxc
ExecStart=/opt/gva-jxc/server -c /opt/gva-jxc/config.yaml
Restart=always
RestartSec=5
# 生产环境建议使用专用账号运行
# User=www-data
Environment=GIN_MODE=release
# 日志交给 systemd 管理
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
```

启用并启动：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now gva-server
sudo systemctl status gva-server          # 查看状态
sudo journalctl -u gva-server -f          # 实时查看日志
```

> 配置加载优先级：命令行 `-c` > 环境变量 `GVA_CONFIG` > gin 模式默认文件 > `config.yaml`。
> 即使不传 `-c`，二进制默认也会读取工作目录下的 `config.yaml`。

### 3.3 前端部署

**（1）构建前端**

```bash
cd web
corepack enable                            # Node 自带 Corepack，启用 pnpm
pnpm install
pnpm build                                 # 产物输出到 web/dist
```

> 构建前确认 `web/.env.production` 中 `VITE_BASE_API = /api`、`VITE_FILE_API = /api`，
> 线上地址按需设置 `VITE_BASE_PATH`。构建产物会以 `/api` 前缀请求后端，
> 由 Nginx 反向代理转发。

**（2）拷贝产物**

```bash
sudo mkdir -p /var/www/gva-jxc
sudo cp -r dist/* /var/www/gva-jxc/
```

**（3）Nginx 静态文件 + 反向代理配置**

创建 `/etc/nginx/conf.d/gva-jxc.conf`：

```nginx
server {
    listen       80;
    server_name  your-domain.com;          # 改为你的域名或服务器 IP

    root  /var/www/gva-jxc;
    index index.html;

    # 前端静态资源（history 路由回退到 index.html）
    location / {
        try_files $uri $uri/ /index.html;
        add_header Cache-Control 'no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0';
    }

    # 后端 API 反向代理：/api/xxx -> http://127.0.0.1:8888/xxx
    location /api {
        proxy_set_header Host              $http_host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        rewrite ^/api/(.*)$ /$1 break;
        proxy_pass http://127.0.0.1:8888;
        proxy_connect_timeout 30s;
        proxy_read_timeout    60s;
    }

    # Swagger 文档（可选）
    location /swagger/ {
        proxy_pass http://127.0.0.1:8888;
    }
}
```

检查配置并重载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

### 3.4 验证部署

```bash
# 后端健康检查（项目提供 /health 接口）
curl -s http://127.0.0.1:8888/health

# 经 Nginx 访问 API
curl -s http://your-domain.com/api/health

# 打开浏览器访问 http://your-domain.com 完成首次初始化
```

## 4. 配置说明

后端所有配置集中在 `server/config.yaml`（Docker 场景为 `config.docker.yaml`），
支持热加载（Viper WatchConfig，修改后自动生效，无需重启）。

### 4.1 数据库连接配置

```yaml
system:
    addr: 8888                # 后端监听端口
    db-type: mysql            # 数据库类型：mysql / pgsql / sqlite 等
    router-prefix: ""         # 路由全局前缀，与前端 Nginx 的 /api 重写规则对应

mysql:
    path: "127.0.0.1"         # 数据库地址
    port: "3306"              # 数据库端口
    config: "charset=utf8mb4&parseTime=True&loc=Local"   # 连接参数（建议保持）
    db-name: "qmPlus"         # 数据库名
    username: "gva"           # 用户名
    password: "你的强密码"      # 密码
    max-idle-conns: 10        # 连接池最大空闲连接数
    max-open-conns: 100       # 连接池最大打开连接数
    conn-max-lifetime: 0      # 连接最大复用时间，0 表示不限制
    log-mode: ""              # SQL 日志级别："" / error / warn / info
```

> 首次部署前（未通过初始化向导前）可保持 `mysql` 连接信息为空，
> 由前端初始化向导填写并完成初始化；也可预先填好，让后端启动即连接。

### 4.2 JWT 签名密钥

```yaml
jwt:
    signing-key: qmPlus    # 签名密钥 —— 生产环境必须改为随机长字符串！
    expires-time: 7d       # token 有效期
    buffer-time: 1d        # 续期缓冲时间（过期前自动刷新）
    issuer: qmPlus         # 签发者
```

生成随机密钥：

```bash
openssl rand -base64 48
```

> 修改 `signing-key` 会使已签发的 token 全部失效（所有用户需重新登录），
> 请选择业务低峰期操作。

### 4.3 日志配置

```yaml
zap:
    level: info                 # 日志级别：debug / info / warn / error
    prefix: '[github.com/flipped-aurora/gin-vue-admin/server]'
    format: console             # console / json（Docker 内建议 json 便于采集）
    director: log               # 日志输出目录（相对工作目录）
    encode-level: LowercaseColorLevelEncoder
    show-line: true             # 是否打印代码行号
    log-in-console: true        # 是否同时输出到控制台（systemd 场景建议 true）
    retention-day: -1           # 日志保留天数，-1 表示不自动清理
    access-req-body: true       # 访问日志是否记录请求体
    access-resp-data: true      # 访问日志是否记录响应体
```

> 生产环境若日志量较大，建议设置 `retention-day: 30` 并开启
> `log-in-console: true`（配合 systemd journal）或使用 json 格式对接采集工具。

### 4.4 文件上传配置

```yaml
system:
    oss-type: local   # 存储方式：local（本地）/ qiniu / minio / aliyun-oss 等

local:
    path: uploads/file        # 前端可访问的路径前缀（相对后端工作目录）
    store-path: uploads/file  # 实际存储目录
```

- 本地模式上传文件保存在后端工作目录的 `uploads/file` 下，后端通过
  `local.store-path` 以静态文件方式对外提供访问；
- 手动部署时确保该目录存在且运行用户有写权限；
- Docker 部署时务必为该目录挂载持久化卷（见 2.1）；
- 若改用对象存储（七牛/MinIO/阿里云 OSS 等），在对应配置段填写密钥，
  并将 `oss-type` 改为对应值，详见 `server/utils/upload/upload.go` 中 `NewOss`。

### 4.5 其他常用配置

```yaml
system:
    use-redis: false        # 是否启用 Redis（启用后需配置下方 redis 段）
    use-multipoint: false   # 多点登录限制（依赖 Redis）

    db: 0
```

## 5. 常见问题排查

| 现象 | 可能原因 | 排查与解决 |
| --- | --- | --- |
| 前端打开后出现 502 Bad Gateway | Nginx 无法连接后端 | 确认 `gva-server` / systemd 服务已启动；检查 `proxy_pass` 地址与端口（Docker 内为 `177.7.0.12:8888`）；`curl 127.0.0.1:8888/health` 自测 |
| 后端启动报 `fatal error config file` | 配置文件路径不对 | 确认 `-c` 指定的路径存在；或设置 `GVA_CONFIG=/path/to/config.yaml`；或把 `config.yaml` 放到工作目录 |
| 数据库连接失败 `Access denied` | 账号密码错误 / 用户主机限制 | 核对 `mysql` 配置段；确认 `gva`@`%` 已授权；Docker 内 host 用 `mysql`、端口用 `3306`（容器内端口） |
| 初始化向导不出现 | 数据库已被部分初始化 | 清空数据库后重启后端，或调用 `POST /api/init/checkdb` 检查返回；确认前端 `/api` 代理正常 |
| 上传图片后访问 404 | 上传目录/静态路径配置不一致 | 确认 `local.path` 与 `local.store-path` 一致且目录存在；确认后端以配置所在目录为工作目录（systemd 的 `WorkingDirectory`）；Docker 场景确认 `uploads` 卷已挂载 |
| 跨域（CORS）报错 | 前后端分离部署但未走同域代理 | 生产环境应使用 Nginx 同域反代（前端与 `/api` 同源）；或调整 `cors` 配置段白名单 |
| 前端构建报内存溢出（OOM） | Node 默认堆内存不足 | `export NODE_OPTIONS=--max-old-space-size=4096` 后重新构建；或使用 `pnpm run limit-build` |
| Docker 构建拉取依赖慢/失败 | 网络问题 | 后端构建已内置 `GOPROXY=https://goproxy.cn`；前端构建可设置 npm/pnpm 镜像源；确认 Docker 已登录与网络可用 |
| arm64（Apple Silicon）无法启动 MySQL | 镜像不兼容 | 将 `image: mysql:8.0.21` 改为 `mysql/mysql-server:8.0.21`（compose 中已有注释说明） |
| 端口被占用 | 8888/8080/13306 被其他进程占用 | `sudo ss -lntp | grep -E '8888|8080'` 定位并处理，或修改端口映射 |
| 登录报 token 相关错误 | JWT 密钥变更导致旧 token 失效 | 属预期行为，重新登录即可；确认各环境 `signing-key` 保持一致 |
| 日志不落盘 | `log-in-console` / `director` 配置 | 确认 `director: log` 目录可写；`log-in-console: true` 时同时输出到 stdout（systemd journal） |

## 6. 生产环境检查清单

- [ ] **JWT 密钥**：`jwt.signing-key` 已改为随机长字符串（`openssl rand -base64 48`）
- [ ] **数据库密码**：MySQL `root` 与应用账号均已使用强密码，生产环境不把 3306 端口暴露公网（Docker 端口映射限定 `127.0.0.1`）
- [ ] **首次初始化**：已完成初始化向导，确认管理员账号可登录，并已修改默认密码
- [ ] **表结构迁移策略**：明确 `disable-auto-migrate` 的取值，生产环境建议开启并制定迁移流程
- [ ] **上传文件持久化**：Docker 场景 `uploads` 卷已挂载；手动部署确认目录权限
- [ ] **数据备份**：MySQL 配置定时备份（如 `mysqldump` + crontab，或 Docker 卷快照），备份文件异地保存；备份命令示例：
  ```bash
  mysqldump -h 127.0.0.1 -P 13306 -u gva -p qmPlus > /backup/qmPlus_$(date +%F).sql
  ```
- [ ] **HTTPS**：生产环境通过 Nginx 配置 443 + 证书（certbot 或云厂商证书），并做 80→443 跳转
- [ ] **防火墙/安全组**：仅放行 80/443（对外）与运维端口；后端 8888 不对公网开放（可仅允许 Nginx 回环访问）
- [ ] **日志策略**：`zap.retention-day` 已设置；日志目录有空间告警
- [ ] **Redis（若启用）**：已设置密码，端口不暴露公网
- [ ] **资源限制**：Docker 场景为容器设置 `mem_limit` / `cpus`；`max-open-conns` 等连接池参数与 MySQL `max_connections` 匹配
- [ ] **监控与告警**：接入健康检查（`/health`）、进程守护（`restart: always` / systemd `Restart=always`）、磁盘/内存告警
- [ ] **版本与回滚**：镜像打 tag（如 `gva-server:1.0.0`），发布前备份旧版本
- [ ] **安全加固**：修改 `email.secret` 等占位密钥；关闭不必要的调试接口；定期更新依赖与镜像
