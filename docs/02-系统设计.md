### 1.2 各层职责

| 层级 | 目录 | 职责 | 不做什么 |
|------|------|------|----------|
| **前端 View** | `web/src/view/` | 页面渲染、用户交互、表单校验 | 不直接操作数据库 |
| **前端 API** | `web/src/api/` | 封装 axios 请求，统一错误处理 | 不含业务逻辑 |
| **前端 Store** | `web/src/pinia/` | 全局状态（用户信息、权限、字典） | 不存页面临时状态 |
| **Router** | `server/router/` | 路由注册、中间件绑定 | 不含业务逻辑 |
| **API** | `server/api/v1/` | 参数绑定与校验、调用 Service | 不写业务逻辑 |
| **Service** | `server/service/` | 核心业务逻辑、事务编排 | 不直接操作 HTTP 请求 |
| **Model** | `server/model/` | GORM 模型定义、数据库操作 | 不含业务逻辑 |
| **Middleware** | `server/middleware/` | JWT、Casbin、CORS、日志、限流 | 不含业务逻辑 |

```
   └─────────┘       └───────────┘      └───────────┘
```

### 4.2 各模块功能矩阵

#### 基础资料模块

| 子模块 | 功能 | 角色权限 |
|--------|------|----------|
| 商品分类 | 树形分类的增删改查、排序、启用/停用 | 老板、店长 |
| 品牌管理 | 品牌的增删改查、启用/停用 | 老板、店长 |
| 供应商管理 | 供应商的增删改查、启用/停用 | 老板、采购 |
| 客户管理 | 客户的增删改查、等级设置 | 老板、销售 |
| 仓库管理 | 仓库的增删改查、启用/停用 | 老板 |

#### 商品中心模块

| 子模块 | 功能 | 角色权限 |
|--------|------|----------|
| 商品 SPU 管理 | 商品的增删改查、导入导出、上下架 | 老板、店长 |
| SKU 管理 | SKU 的增删改查、价格设置、条码管理 | 老板、店长 |

#### 采购中心模块

| 子模块 | 功能 | 角色权限 |
|--------|------|----------|
| 采购单管理 | 创建、编辑、删除采购单 | 采购 |
| 采购审核 | 审核采购单（通过/驳回） | 老板、店长 |
| 采购入库 | 执行入库，增加库存，生成流水 | 仓管 |
| 采购取消 | 取消待审核/已审核的采购单 | 采购、老板 |

#### 销售中心模块

| 子模块 | 功能 | 角色权限 |
|--------|------|----------|
| 正常销售 | 创建销售单 → 出库 → 扣减库存 | 销售 |
| 退货退款 | 创建退货单 → 关联原单 → 入库 → 恢复库存 | 销售（需审核） |
| 换货 | 创建换货单（出+入） → 关联原单 → 增减库存 | 销售（需审核） |
| 销售取消 | 取消待出库的销售单，释放锁定库存 | 销售 |

#### 库存中心模块

| 子模块 | 功能 | 角色权限 |
|--------|------|----------|
| 库存查询 | 按仓库/SKU/商品多维度查询实时库存 | 所有人 |
| 库存预警 | 低于预警数量的 SKU 高亮提示 | 老板、仓管 |
| 库存流水 | 按时间/SKU/业务类型查询变动历史 | 老板、仓管 |
| 直接入库 | 不关联采购单的入库（如赠品入库） | 仓管 |
| 直接出库 | 不关联销售单的出库（如损耗出库） | 仓管 |

#### 盘点中心模块

| 子模块 | 功能 | 角色权限 |
|--------|------|----------|
| 创建盘点单 | 选择仓库，创建盘点任务 | 老板、仓管 |
| 录入盘点数 | 逐 SKU 录入实际盘点数量 | 仓管 |
| 完成盘点 | 差异对比 → 自动调整库存 → 生成流水 | 老板（审核） |
| 盘点记录 | 查看历史盘点记录和差异明细 | 老板、仓管 |

#### 扫码枪模块（v2-M3 新增）

| 子模块 | 功能 | 角色权限 |
|--------|------|----------|
| 扫码上架 | 小程序扫码 → 投递到已绑定收银台 | 老板、店长、销售 |
| PC 轮询消费 | 拉取本会话未消费条目并自动加入购物车 | 老板、店长、销售 |
| 收银台码管理 | PC 生成/重置收银台码 | 老板、店长（销售仅绑定校验） |
| 小程序绑定 | 输入收银台码校验并绑定 | 老板、店长、销售 |

> 接口级权限（casbin）见 `docs/sql/pos-permissions.sql`：888/9001 全 6 接口，9002 业务 4 接口（无码管理权）。

## 五、核心业务流程

### 5.1 采购入库流程

```
采购员                    老板/店长                  仓管
  │                         │                        │
  │  1.创建采购单            │                        │
  │  (状态:待审核)            │                        │
  │────────────────────────►│                        │
  │                         │  2.审核采购单            │
  │                         │  (状态:待审核→已审核)     │
  │                         │───────────────────────►│
  │                         │                        │  3.执行入库
  │                         │                        │  ┌─────────────────┐
  │                         │                        │  │ 3.1 校验状态     │
  │                         │                        │  │ 3.2 开启事务     │
  │                         │                        │  │ 3.3 逐条更新库存 │
  │                         │                        │  │ 3.4 逐条生成流水 │
  │                         │                        │  │ 3.5 更新采购单状 │
  │                         │                        │  │     态→已入库   │
  │                         │                        │  │ 3.6 记录操作日志 │
  │                         │                        │  │ 3.7 提交事务     │
  │                         │                        │  └─────────────────┘

  取消流程：采购员/老板在「待审核」或「已审核」状态可取消 → 状态→已取消
  删除流程：仅「待审核」状态可删除
```

```
  │                                               │  │    增加          │
  │                                               │  │ 2.3 创建销售单   │
  │                                               │  │    状态:待出库   │
  │                                               │  └─────────────────┘
  │                                               │
  │  3.确认出库                                    │
  │──────────────────────────────────────────────►│
  │                                               │  4.执行出库
  │                                               │  ┌─────────────────┐

```

## 八、设计原则

### 8.1 后端设计原则

1. **分层解耦**：严格遵循 API → Service → Model 三层，层间通过接口调用，不跨层访问
2. **事务集中在 Service**：所有多表写操作在 Service 层显式管理事务边界
3. **库存变更必写流水**：任何 quantity 变化必须同步写入 stock_log，不留数据黑洞
4. **软删除为主**：业务数据使用 GORM 软删除，保留数据追溯能力
5. **状态机驱动**：采购单/销售单/盘点单使用状态机模型，状态流转清晰可控

### 8.2 前端设计原则

1. **组件复用**：抽取通用表格、表单、搜索栏等业务组件
2. **权限驱动 UI**：按钮/菜单根据用户权限动态显隐
3. **乐观更新**：库存查询等高频操作优先展示缓存数据，后台静默刷新
4. **表单校验前置**：必填项、格式校验在提交前完成，减少无效请求

### 8.3 数据安全原则

1. **金额用 DECIMAL**：杜绝浮点精度导致的财务误差
2. **库存操作用事务**：入库/出库/盘点均包裹在数据库事务中
3. **并发用乐观锁/悲观锁**：库存扣减使用 `WHERE quantity >= N` 条件防超卖
4. **操作可追溯**：关键操作写入 stock_log（库存）或 operation_record（系统操作日志）
