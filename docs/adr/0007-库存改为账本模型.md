# ADR-0007：库存从「计数器」改为「账本」，且账本核心不交给代码生成器

- 状态：提议中（待确认后实施）
- 日期：2026-10-27
- 相关：`16-库存账本核心设计.md`、`docs/adr/0004-金额对外用元对内用分.md`

## 背景

现有实现把库存建模成两个东西：可变余额 `stock.quantity` + 描述性日志 `stock_log`。
前 8 轮的整改一共修了 15 个以上库存/金额相关缺陷（丢失更新、锁量负数、
收银流水 before/after 写反、盘点覆盖无视在途、退货按总件数限额……）。

这些缺陷看起来彼此无关，但根因是同一个：**余额是真相，日志只是注释**。
所以余额一旦写错，没有任何机制能发现；成本根本不存在，毛利是估算；
单据可改可删，账不可解释。

同时暴露出一个更适合记下来的教训：**GVA 的代码生成器（一表一 CRUD）适合主数据，
不适合账本。** 把 `stock` 当成一张普通业务表、用生成器那套思路写增删改查，
必然得到"计数器 + 日志"，因为生成器的世界观里没有"不可变事实"这个概念。

## 决策

1. **引入账本模型**：新增不可变的 `stock_move`（有符号 qty、冻结的 unit_cost、来源单据、
   幂等键、`reversal_of`），`stock` 降级为可由账本重算的物化余额。
2. **余额必须可对账**：三条不变量查询写成测试 + 做成"一键对账"页面。
   余额漂移是成熟产品也承认的现实（ERPNext 专门有 invariant check 报表），
   区别在于有没有检测手段。
3. **成本冻结在发生那一刻**：`stock_move.unit_cost` 记录出库时的结转成本；
   退货使用**原单成本**，不使用当前成本。`goods_sku.cost_price` 降级为"参考进价"。
4. **单据 posted 之后不可变**：更正走红冲（`reversal_of`），取消不再是改状态。
5. **禁止跨期回填**：`occurred_at` 所属期间必须打开；已结账期间只能在当期红冲。
   这条约束的目的不是会计严谨，而是**让"重过账(repost)"这个机制根本不需要存在**。
6. **账本核心不交给 GVA 代码生成器**：`stock_move` 只有 `INSERT` 路径，
   由手写的过账函数统一写入；代码生成器生成的 CRUD 只用于主数据（商品/客户/供应商等）。
7. **v1 采用移动加权平均**，但把成本方法隔离在过账逻辑内部（`unit_cost` 是入参/出参），
   将来换 FIFO 只加 `stock_layer` 表，不动单据与余额。

## 理由

- **不变量 > 事务**：事务保证一次操作的原子性，不变量保证一万次操作之后账还是对的。
  这是库存系统与普通 CRUD 系统的分水岭。
- **成本是刚需不是加分项**：店主真正想知道的是"这个月赚了多少"，而这只能由冻结的成本算出。
- **不可变是审计的前提**：不允许改写历史，才谈得上"解释为什么账上是这个数"。
- **约束换简单**：禁止跨期回填，换来"账本永不被改写"，从而省掉整套 repost 机制。
  这是一个主动的取舍，代价（上月漏录只能补在本月）必须在文档里明说，不能装作没有。

## 后果

- `sale_item.direction` 删除；换货拆成 `sale_return` + `sale_out` 两条账本移动。
- `stock.lock_quantity` 删除，改为 `stock_reservation`（有归属、有到期）。
- 看板毛利改为从账本计算，历史期间若无成本数据要显式标注，不能假装准确。
- 需要新增：`stock_move`、`stock_reservation`、`accounting_period`、`stock_balance_snapshot`，
  以及一套"过账函数 + 不变量测试"。
- 现有 8 轮整改的成果**不作废**：鉴权、权限矩阵、并发条件更新、金额分制、契约测试、
  集成测试体系全部继续有效；这次改的是**数据模型的语义**，不是推翻工程基础。

## 不采用「直接用现成开源系统」的原因

对"练手 / 作品集 / 观测商业产品"这个目标，部署一套 ERPNext 学到的是运维，不是建模。
本项目的价值恰恰在于**亲手把账本做对**，并把判断过程记录下来。
（如果目标是"尽快给店里用上"，结论会反过来——那应该直接上 ERPNext。）

## 何时重新评估

- 若引入批次毛利需求（季末清仓分析）→ 升级为 FIFO，新增 `stock_layer`。
- 若出现多仓调拨/多门店 → 需要重新建模"库存归属"，届时另开 ADR。
