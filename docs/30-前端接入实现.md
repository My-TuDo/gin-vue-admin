## 二、单据页：服务端筛选 + 分页

### 2.1 查询参数

当前 Tab 对应端点，统一传：

- page、pageSize=20；
- status（当前状态按钮，空=全部）；
- keyword（300ms 防抖）；
- warehouseId；
- startAt / endAt + dateField（创建时间/过账时间）。

未在界面暴露 partnerId、reversed、sourceType：往来单位可被 keyword 覆盖；
已红冲行在列表用状态标签标注；红冲 Tab 默认看全部来源。后端仍支持这些参数，后续需要再加控件。

### 2.2 计数与分页

- 列表 total 一律使用接口返回值；不再用当前页/前 100 条计算；
- 状态按钮计数：每个状态用 pageSize=1 请求一次 total（后端本轮没有聚合计数接口）；
- 顶部 Tab 计数：进入页面/写操作后各请求一次 pageSize=1，作为全局总数；
  一旦启用 keyword/状态/仓库/日期筛选，顶部计数隐藏，避免为计数跨 Tab 请求，也避免与筛选结果混淆；
- 状态计数随 keyword/仓库/日期/dateField 变化重算；分页只请求当前页；
- 空态用 total===0 与 listError 区分「没有数据」和「请求失败/无权限」。

### 2.3 采购退货列表字段

列表直接使用服务端返回的：

- supplierName：供应商名称；
- warehouseName：仓库名称（显示在供应商下方）；
- itemCount：明细项数（显示在退货金额下方）。

详情仍按 ID 取，字段回退到本地 partner/warehouse map。

## 四、壳层对账：只读最近结果

- 进入 /jxc 只调 GET /jxc/ledger/reconcile/last，不触发全仓扫描；
- 状态：
  - 无 checkedAt：尚未对账；
  - stale=true：对账已过期（warning）；
  - ok=true：账实相符；
  - ok=false：对账异常；
  - 接口失败：对账不可用；
- title 展示 范围 + 检查时间 + 耗时 + SKU 数；
- 60s 静默轮询 /last，避免页面停留时一直挂着过期的「账实相符」；
- 顶栏点击：不在库存页 → 跳 /jxc/inventory?reconcile=1；已在库存页 → 广播 jxc:run-reconcile，
  由库存页直接调 /reconcile 并打开结果弹窗；
- 手动检查成功后，库存页继续广播 jxc:reconcile，壳层重新读 /last。

## 八、已知限制与待确认

1. 状态/页签计数是额外轻量请求：每个状态/页签一次 pageSize=1；
   进入单据页约 10 个请求（5 个页签 + 5 个状态）；keyword/仓库/日期筛选约 6 个
   （1 个列表 + 5 个状态计数，顶部 Tab 计数隐藏）；切换状态/翻页只请求 1 个列表。
   后端若补聚合计数，可降到 1 个。
2. 日期/仓库已接，partnerId/reversed/sourceType 未做控件；keyword 可覆盖往来单位名称/编码。
3. 对账是快照：60s 轮询只更新「是否过期」；检查后发生新账本行，最多等一个轮询周期才变「已过期」。
   顶栏 title 始终带检查时间，不把它当成实时余额证明。
4. 销售单数口径待确认：dashboard todaySalesOrders / 月报 salesOrders 目前是
   「全部已出库（含已红冲）」；金额/成本已扣红冲与退货。前端按接口显示，不二次扣减；
   若产品要净单数，需后端扣 revSaleAgg.Cnt 并同步月报，详见 31/32。
5. 角色：8881/9002/9003 均已完成真实登录 UI 点触；9001/9002/9003 的 9 条基础策略已落库并重启，
   JXC 210 + 基础 9 = 219 条，详见 31。
6. 原子开单失败路径：已用「停用 SKU」在 UI 验证错误提示与零残留；库存不足/并发仍由后端测试覆盖。
7. 采购退货红冲：列表/详情入口、专用弹窗、红冲记录来源已接，PR-004/RC-018 验收；详见 31。
